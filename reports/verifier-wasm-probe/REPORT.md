# Проба WASM-сборки верификатора (предпроектная работа, до 8-live)

Решение владельца 11.11.2026 (stage-decisions): верификатор — Go с
переиспользованием пакетов ядра как go-модульная зависимость, без
второй реализации протокола, без P2P-стека в зависимостях; JS-сборка —
через GOOS=js. Эта проба проверяет сборочную сторону решения до
написания продуктового кода. Продуктовый код верификатора НЕ создаётся;
игрушечный пример живёт только здесь и в продуктовые пакеты
не переносится.

## Состав

| Файл | Назначение |
| --- | --- |
| `toy/go.mod`, `toy/go.sum` | вложенный go-модуль: `require` ядра + `replace github.com/rumatakira74/equality-trust-networks => ../../../` — модель «ядро как go-модульная зависимость» |
| `toy/main.go` | игрушечный потребитель: crypto (ключ/адрес/подпись DER), wire (canonical-кодек, AttestStatement.Hash, StateLeaf roundtrip), smt (Prove/VerifyProof, 256 соседей), threshold (N-из-M), cons (Signer, Verify чекпоинта), present (AppIdentity, Verify) |
| `build.sh` | воспроизведение: `go mod tidy` (GOPROXY=off — только кэш модулей), нативный sanity-прогон, `GOOS=js GOARCH=wasm go build`, `go vet` |
| `build.log` | вывод прогона (ниже — те же данные) |

Бюджет прогона: GOMAXPROCS=6 (≤6 ядер из 8), память свободная
~10 ГБ (лимит <2 ГБ не достигался).

## Результат

**Собирается.** `GOOS=js GOARCH=wasm go build` игрушечного модуля,
импортирующего пакеты ядра через go-модульную зависимость, проходит
без ошибок и без каких-либо тегов/обходов: `toy.wasm` — 5 364 846 байт
(~5,1 МБ, вместе с Go-runtime и crypto). `go vet` чистый.

Дополнительно (вне игрушечного модуля, на корне репозитория):
`GOOS=js GOARCH=wasm go build ./core/present ./cons ./core/crypto
./core/wire ./core/smt ./core/threshold ./core/attest` — тоже
проходит: весь verify-контур ядра компилируется под js/wasm как есть.

Нативный sanity-прогон (linux/amd64) всех путей игрушки — зелёный:
деривация адреса, канонический хеш утверждения, roundtrip листа
состояния, подпись/проверка DER, H(address ‖ app_id), Merkle-доказательство
(найдено и сходится, 256 соседей), чекпоинт с пороговой подписью
`cons.Verify` = nil, `threshold.Verify` = 1/1, отказ пустого предъявления.

## Что НЕ собирается / не проверялось и почему

- **P2P-пакеты (`net/`, `mobile/`, `cmd/`) в сферу пробы не входят**
  (по мандату) — их js/wasm-сборка не проверялась. Ожидание (не
  проверено): не собираются — libp2p требует ОС-сетевых API,
  отсутствующих в js; верификатору эти пакеты не нужны (решение 11.11:
  без P2P-стека в зависимостях), графе зависимостей verify-контура их
  нет — что и подтверждает проба.
- `gomobile bind` в пробу не входил (JS-цель проверена GOOS=js; JVM-цель —
  прецедент этапа 6). Прецедент по среде (stage-decisions 01.11): gomobile
  bind на Go 1.27 требует `-ldflags "-checklinkname=0"` из-за
  `wlynxg/anet` (WebRTC-транспорт libp2p, только Android, `go:linkname`
  на `net.zoneCache`). У верификатора `net/` в графе зависимостей нет,
  поэтому ожидание — флаг не потребуется; проверяется при реализации
  верификатора, не в этой пробе.
- Запуск `toy.wasm` в браузере/node (wasm_exec.js) не выполнялся:
  цель пробы — собираемость (компиляция) и отсутствие P2P в графе,
  не исполнение; семантика путей подтверждена нативным прогоном того
  же кода.

## Выводы

1. Решение 11.11 сборочно реализуемо как есть: пакеты verify-контура
   (`core/crypto`, `core/wire`, `core/smt`, `core/threshold`,
   `core/attest`, `cons`, `core/present`) компилируются под
   GOOS=js GOARCH=wasm без изменений, тегов и обходов.
2. Внешние зависимости verify-контура — только `golang.org/x/crypto`
   (argon2, blake2b, cryptobyte) и `golang.org/x/sys`; P2P-стек
   (libp2p, quic, pion, sqlite) в граф не попадает — «без P2P»
   выполняется автоматически, отдельного вырезания не требуется.
3. Модель «ядро как go-модульная зависимость» работает на практике:
   вложенный модуль с `replace` собирается и под linux, и под js/wasm.
   Публикация для внешнего потребителя — обычный go-модуль
   (псевдоверсия/тег при реализации).
4. Размер WASM игрушки — ~5,1 МБ (весь verify-контур + runtime).
   Ориентир для продуктового верификатора: тот же порядок; замеры и
   решение по размеру — после 8-live (проектирование API —
   `docs/verifier-api-design.md`, пометка о нестабильности).

Проба: Go 1.27.3 linux/amd64, 11.11.2026.
