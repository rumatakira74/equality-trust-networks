# Отчёт: тема net-DoS (A3) — защита от асимметричного DoS

Ветка `net-dos-a3` от `main` (`963d441`). Промпт: `prompts/net-dos-a3-prompt.md`.
Находка аудита A3 (высокая, подтверждена повторным аудитом 01.11.2026):
Argon2id (32 МиБ) и PoW проверялись у транзакции ДО подписи, лимитов
по пиру не было, peer score отсутствовал — анонимный пир заставлял
любой узел выполнять дорогую валидацию до отклонения по подписи.

## 1. Порядок валидации: до и после

### До (main, `net/gossip.go` `cheapCheck`)

1. `network_id`, `protocolVersion`, наличие PoW, допуск C9, тип
   алгоритма PoW — дёшево;
2. **Argon2id/PoW-проверка** (для register/mint — Argon2id 32 МиБ) —
   ДО подписи: мусорный конверт с корректным PoW-полем и случайным
   nonce запускал дорогую проверку у каждого узла;
3. подпись (для неизвестного кошелька — пропускалась);
4. seq/prev; затем `applyLive` → `ledger.Apply` (PoW ядром ещё раз).

Путь валидатора темы и `handleTxFromPeer` гоняли `cheapCheck` дважды
на одно сообщение (двойной Argon2id для валидного register/mint).

### После (ветка)

Единый путь приёма `relayAdmit(tx, from)` (`net/gossip.go`), вызывается
валидатором темы и `handleTxFromPeer` (сообщения до регистрации
валидатора); для прошедших валидатор сообщений повтор не выполняется
(`verified`), Argon2id на сообщение — ровно один:

1. дешёвые структурные проверки `cheapCheck`: `network_id`,
   `protocolVersion`, наличие/тип PoW, допуск C9, seq/prev против
   локального реестра, подпись ECDSA P-256 (каноничный DER + low-s,
   этап 9; для register ключ из payload, для остальных — ключ
   кошелька);
2. **tx незарегистрированного кошелька — дешёвый отказ** (только
   полный узел): ядро в тот же момент дало бы `E_UNKNOWN_WALLET`
   (C5), множество принимаемых tx не меняется; Argon2id для
   неизвестного отправителя не выполняется вовсе (ключа нет —
   подпись проверить нельзя, значит и дорогая работа не запускается);
   догоняющая доставка таких tx — сверкой (журнал упорядочен);
   лёгкий узел (без реестра) неизвестность проверить не может — для
   него путь прежний (подпись пропускается), дорогой PoW ограничен
   бюджетом пира;
3. подпись — только после неё бюджет дорогих операций и
   Argon2id/PoW (`verifyPoW`): мусор с битой подписью отсекается до
   дорогой работы (счётчик `expensive_checks` не растёт — тест 1).

Ядро (`core/ledger/validate.go` `applySigPowTime`) и раньше проверяло
подпись (C8) до PoW (C10/C11) — не менялось. `protocolVersion` не
поднимается: wire-формат и правила приёма валидных tx не изменились,
меняется только порядок внутренней работы узла.

## 2. Лимиты по пиру (бюджет дорогих операций)

`net/dos.go`, константы (поведение узла, НЕ протокола; в genesis не
добавлялись):

| Параметр | Значение | Обоснование |
| --- | --- | --- |
| `DosExpensiveBudget` (N) | 32 проверок Argon2id на пира | честный пир не шлёт десятков register/mint в секунду (mint — раз в период на кошелёк, register — раз на устройство); 32 × ~30 мс (32 МиБ, хост; на телефоне дольше) ≈ 1 с CPU на пира за окно |
| `DosExpensiveWindow` (T) | 10 с (скользящее) | окно переживает короткие всплески синхронизации; восстановление бюджета — тестом 6 |
| `DosMaxConcurrentHard` | 2 параллельных Argon2id на узел | память: 2 × 32 МиБ = 64 МиБ на пике (аудит A3: «ограничить число параллельных Argon2»); занятый семафор — дешёвый отказ без копления очереди |

Превышение бюджета: дорогая операция НЕ выполняется, сообщение дёшево
отклоняется (`errDosBudget`, счётчик `budget_rejected`), пир штрафуется;
догоняющая доставка валидных tx — сверкой (журнал упорядочен, сверка
применяет ядром, дешёвый дедуп по якорям №41). Разрыв соединения —
только по порогу счёта (ниже). Значения переопределяются в
`NodeConfig` (`DosExpensiveBudget/Window/MaxConcurrentHard`) для
тестов; прод-дефолты — константы.

## 3. Peer score (libp2p `WithPeerScore`)

`net/dos.go` `peerScoreParams` + `dosTracker`; подключен в `newPubSub`
(`pubsub.WithPeerScore`). Состав:

- **Тема tx** (`TopicScoreParams`): время в mesh (P1, +0.01/с, кап 3600),
  первые доставки (P2, +1, кап 64, распад 0.5/с), невалидные сообщения
  (P4, −16, распад 0.5/с) — P4 растёт автоматически по
  `ValidationReject` валидатора;
- **Счёт приложения** (`AppSpecificScore` = `dosTracker`, вес 1):
  штрафы: невалидная подпись −8, неверный PoW −4, структурный мусор
  −4, исчерпание бюджета −4, неизвестный кошелёк −2; награда за
  валидную tx +1 (кап +16); экспоненциальный распад к нулю, половина
  за 60 с — честная активность восстанавливает счёт, штрафы не
  «отработать» полезной нагрузкой (награда меньше штрафов);
- **Пороги pubsub**: GossipThreshold −10 (пир вырезается из mesh —
  пониженный приоритет/бандвит), PublishThreshold −40,
  GraylistThreshold −80 (pubsub игнорирует пира до валидации —
  дешёвый отсечённый путь), OpportunisticGraft 2; BehaviourPenalty
  −16/8/0.9 (нарушения роутера: преждевременный re-graft, IWANT без
  доставки);
- **Разрыв соединения — крайняя мера**: `maybeDisconnect` при счёте
  ниже −64 (8+ мусорных подписей подряд);
- IP-colocation отключён (вес 0): все пиры localhost-тестов в одной
  /24; включение с реальными данными о подсетях — рекомендация блока
  8-live (не предмет темы).

Обоснование весов: невалидная подпись — прямой признак мусора
(максимальный штраф); неверный PoW при валидной подписи — мусор от
владельца ключа; счёт приложения и P4 дублируют сигналы сознательно:
pubsub-часть управляет mesh/грейзлистом, приложение — разрывом.

## 5. Прогон с флудером (headless)

процесс (CPU/RSS по `/proc/PID`), честный публикатор валидных
VOUCH (лёгкий PoW), флудер — raw gossipsub без валидатора (модель
атакующего, как спам-тест 4.11.3). Мусор: MINT-конверты с корректным
PoW-полем (argon2id + случайный nonce), битой подписью, случайным

## 8. Границы и открытые пункты

- Бюджет ограничивает путь приёма gossip; сверка (pull) применяет
  журнал ядром без `cheapCheck` — стоимость Argon2id там ограничена
  размером батча (`SyncBatch` = 512) и требованием валидных подписей
  (C8 до C10/C11 в ядре): атака требует зарегистрированных ключей.
  Осознанное решение, вне предмета A3 (admission-путь находки).
- Лёгкий узел не может дёшево проверить неизвестность кошелька (нет
  реестра): его защита от мусорного Argon2id — бюджет пира и
  pubsub-score (грейзлист), не дешёвый отказ. Полный узел (в т.ч.
  телефон в полном режиме) получает дешёвый отказ.
- IP-colocation фактор pubsub-score отключён (localhost-тесты в
  одной /24) — кандидата на включение в блок 8-live.
- `FINDING` вне мандата: не обнаружено; блокеров прогона не было.
