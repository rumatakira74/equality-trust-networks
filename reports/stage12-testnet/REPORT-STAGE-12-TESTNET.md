## Replay-изоляция (27)

Подписанные tx (mint, слепая сборка с -no-submit) сетей A, B и
глобальной публикуются во все направления:

| направление | результат |
| --- | --- |
| tx A (rec) → B (std) | reject/**E_NET** |
| tx B (std) → A (rec) | reject/**E_NET** |
| tx global → A | reject/**E_NET** |
| tx global → B | reject/**E_NET** |
| tx A → global | reject/**E_NET** |
| tx B → global | reject/**E_NET** |

## Находки

1. **FINDING-replay-live-divergence.txt (коммит `4b57344`)**: mint,
   собранный в периоде N и опубликованный в N+1, принимается живой
   сетью (валидация по часам узла на момент apply) и отвергается при
   replay (пинирование на timestamp_claim — момент сборки, №40 этапа
   9): холодная сверка/рестарт расходится с живыми узлами
   перманентно. При 30-суточных периодах окно ничтожно (сборка до
   границы месяца, публикация после, в пределах C9 ±30 мин), при
   коротких — систематично. Прогон обходится паттерном «сборка и
   публикация внутри одного периода»; фикс — отдельный этап (решения
   владельца от 01.11.2026 подтверждены), здесь не трогалось.
2. **std-семантика «потронутых» единиц** (подтверждение расхождения
   №6 отчёта этапа 12): при fresh_transfer_window 0 (шаблон 8) первое
   списание переводит ВСЕ когорты кошелька в Liquid — после этого
   сгорание сбросом на них не действует; нетронутые когорты сгорают
   на границе (артефакты 25a–c: 1000 сгорела, 550+400 живут).
3. **Окно челленджа при коротких периодах** (блокер 2): слот
   масштабируется длиной периода, но квоты посевного круга обязаны
   заявляться с периода 1 (quota_reset, diff=1) — при genesis в
   прошлом их слоты недостижимы с окном шаблона. Требует решения
   владельца для живых сетей с короткими периодами (если такие
   возникнут); в спеку — семантика слота при period_seconds.
