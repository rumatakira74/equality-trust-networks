## 2. Задача 1 — genesis-утилита `cmd/tnp-testnet` (bdf1838, 73b8949)

- **Декодер genesis-пакета** (core/wire/genesis_decode.go — аддитивный
  файл, правило 3: поведение ядра не меняется): до этапа 8 genesis
  кодировался, но не декодировался — сеть можно было собрать только
  кодом. Round-trip тест: блоб восстанавливается байт в байт,
  manifest_hash сходится, unknown-поля отвергаются.
- **generate**: genesis.bin (пакет одним блобом), manifest.json
  (параметры KNOWLEDGE 4/17: выпуск 1000/мес, окно накопления 6, K=3,
  слоты 3/5/10, R=10% первых 12, демередж 1%/3000, burn-комиссия,
  мораторий 14 сут, D=48 ч, P=3000/P_max=30000, окно челленджа ±48 ч,
  допуск ±30 мин, эпоха 24 ч №16, PoW №9), закрытая сеть:
  network_access=invite_only, вход invite_only_vouch, ключ приглашения
  в genesis-записи (spec/02 2.1, в манифесте не публикуется),
  network_id = 32 байта; seed-список (формат 12.3, подписи 3
  детерминированных ключей проекта; в invite_only bootstrap его не
  использует — артефакт формата); приглашения invite.txt
  (`tnp://invite?net=…&genesis=…&key=…&peer=…`, QR рендерит
  приложение); таблица слотов челленджа посевного круга с достижостью.
- **tx-режимы** для прогона: register (синтетическая аттестация —
  деривация корня общая с приложением), vouch, mint (±save/no-submit
  для эквивокации), publish, transfer, cancel, migrate
  (propose/cancel), evidence, slots.
- **Сборка сети в эмуляторе** (артефакты reports/stage8/testnet/):
  tnp-node -genesis-file (узлы), приложение (genesis-файл через
  files/networks — debug: run-as, release: внешний каталог), всё на
  одном genesis (manifest_hash bc944df5…). Хост-смок: связка узлов,
  регистрация, синхронизация. Эмулятор: полный прогон (п. 3) и
  приложение в тестнете (peers 2, журнал 11 tx по событию identify).

## 3. Задача 4 — эмуляторный прогон (reports/stage8/testnet-demo.sh, testnet-demo-output.txt)

Pixel 9 (API 36, x86_64), узлы ВНУТРИ эмулятора (одни часы), сдвиги
`cmd alarm set-time` (после каждого сдвига узлы перезапускаются —
TLS-сертификаты libp2p генерируются на старте). Полный путь нескольких
узлов на тестнете (real-параметры, окно ±48 ч):

| Шаг | Результат |
| --- | --- |
| Выпуск в окне челленджа | V3 период 1 **в окне** — accept (2000); период 2 **вне окна** — reject/E_POW_HARD. Позитив и негатив, окно реально проверяется при apply (8.0.2) |
| Эквивокация | две ветки минта периода 4 (один seq/prev, разные nonce): accept + **conflict/EQUIVOCATION_BRANCH_LOST**; конфликтная ветка доставлена |
| Отложенный перевод | 3500 > P=3000: accept, комиссия 35, средства locked на 48 ч; **отмена** до дедлайна — accept, возврат. Отрицательный тест: та же сумма в периоде 6 (когорты не переводимы) — E_BALANCE |
| Обычный перевод | 100 + комиссия 1 (сжигается), получатель получил ровно 100 |
| Регистрация | W1 (гардианы V2+V3), синтетическая аттестация, усиленный PoW — accept |
| Поручительства | vouch V3→W1 — accept; vouch V1 (0 завершённых периодов) — **E_VOUCH_PERIODS** (V3-условие работает) |
| Evidence | на эквивокации (Kind=EQUIVOCATION) — accept, V3 **flagged**, приостановка выпуска; повторный vouch V3 — **E_VOUCH_FLAGGED** (№14) |
| Миграция | propose (подписи гардианов V2+V3, 2 из 3) — accept; cancel старым ключом — accept |
| Холодный старт | свежий узел C без БД синхронизировал весь журнал (11 tx) с нуля |

**Приложение, полный путь (песочница, скриншоты 03–09):** биометрия
(энролл отпечатка в эмуляторе) → PIN обычный + тревожный → гардианы
(реестр синхронизирован) → регистрация (биометрическая подпись,
усиленный PoW) → vouch×3 от посевного круга → **ACTIVE** → выпуск
периода 12 при периоде 13 (баланс 1000 − R ≈ 901) → перевод 50 +
комиссия 1 (баланс 850) → **тревожный PIN**: принудительный стоп,
вход тревожным — режим-приманка (остаток 847 по легенде, история
пуста, интерфейс неотличим), вход обычным — реальный кошелёк на месте.
Миграция протокольно проверена на тестнете; экраны приложения —
без регрессий (этап 7). **Приложение в тестнете:** genesis-файл,
подключение к узлам, синхронизация журнала 11 tx.

## 10. Невыполненное и допущения

- Окно челленджа в песочнице открыто параметром (учебный оверрайд,
  как в этапе 7): при реальном ±48 ч полный путь приложения в
  песочнице невозможен (№39 — у V2/V3 нет достижимых периодов);
  реальное окно проверено на тестнете в обе стороны.
- Миграция в приложении (экраны) не перегонялась поэтапно —
  протокольный путь (propose/cancel) проверен на тестнете, экраны
  без регрессий (этап 7, flutter test).
- Имя тестнета `tnp-testnet-alpha` выбрано из условия достижимости
  окон челленджа посевного круга (V3: периоды 1 и 4) — тестовая сеть,
  ключи детерминированы; живая сеть генерирует случайные ключи.
