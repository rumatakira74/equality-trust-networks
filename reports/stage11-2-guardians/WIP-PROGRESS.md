## Блокер снят (причина найдена и подтверждена владельцем)

Блокер из BLOCKER-emu-app-install.md был НЕ в сборке: вчерашний рабочий
release-APK воспроизводил тот же симптом. Причина — AVD Pixel_9 (и tnp_api35)
имели заданный системный PIN (остался от прошлых прогонов) → user 0 в
состоянии RUNNING_LOCKED после загрузки → сторонние приложения не
запускаются («activity does not exist», result -92, пакет выглядит
disabled, каталог данных не создаётся). Лечение: `emulator -avd Pixel_9
-wipe-data`. Замечание владельца: в уборку прогонов с системным PIN
добавлять wipe-data AVD, иначе следующий этап упрётся в тот же блокер.

## Находки прогона (кандидаты в PENDING финального отчёта)

1. IME (известная нестабильность, stage11-prep находка 3) портит длинные
   hex-строки: подпись 140–142 символа теряет символы при цельном вводе;
   надёжно — ввод чанками по 20 с проверкой поля (uiautomator dump) перед
   каждым действием. Один propose отклонён E_GUARDIAN_UPDATE из-за битой
   подписи (повтор с проверкой полей — accept). Отклонённая транзакция
   цепочку не двигает — повтор безопасен.
2. Открытая клавиатура перекрывает нижние кнопки ListView: тапы «мимо»
   (двойное добавление пары, тап по клавиатуре вместо кнопки). Перед каждым
   тапом — dump свежих координат; закрытие IME перед кнопками.
3. Дважды после неудачной/просроченной биометрии (промпт без касания)
   приложение замерзало (PIN-диалог не отвечает, Cancel не работает);
   лечится force-stop + перезапуск. Не воспроизводится при немедленном
   касании сенсора после появления промпта. Кандидат в PENDING: поведение
   платформенного слоя при таймауте биометрии.
4. Сдвиг часов: `-qemu -rtc base=<+50ч>` применён, но после загрузки
   `adb shell date` показывает реальное время (эмулятор, вероятно,
   синхронизируется с хостом) — проверяется; auto_time выключен на всякий
   случай. Вступление смены в силу ещё не показано.
