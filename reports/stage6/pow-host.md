# Замеры моста и PoW на хосте (этап 6, разделы 12.1; вопрос №9)

Окружение: Intel Core i7-1065G7 (8 потоков), Ubuntu 24.04, Go 1.27.2.
Бенчмарки: `go test ./mobile/ -bench . -benchtime 2x` (mobile/bench_test.go).
Замер одной итерации Argon2id — отдельный прогон (x/crypto/argon2 v0.58.0).

| Замер | Значение |
| --- | --- |
| Лёгкий PoW, таргет 2^24 (0x0000010000000000) | 590 мс/поиск |
| Лёгкий PoW, таргет 2^20 (0x0000100000000000) | 111 мс/поиск |
| Argon2id, одна итерация 32 МиБ × 1 × p=1 | ~30 мс |
| Argon2id, одна итерация 64 МиБ × 1 × p=1 | ~60–69 мс |
| Полный поиск mint-PoW: Argon2id 32 МиБ, таргет 2^57 (~128 итераций) | 9,5 с |
| Полный поиск mint-PoW: Argon2id 64 МиБ, таргет 2^57 | 39,3 с |
| Вызов моста (сборка tx + protobuf-кодирование + разбор, без PoW) | 5–10 мкс |

Скорость SHA-256 по замеру 2^24: ~28 млн хешей/с на ядро.

## Текущие значения TestGenesis (этап 3, предположение) — НЕДОПУСТИМО тяжелы

- TargetLight = 0x0000000100000000 (2^32): ~159 с на хосте, на телефоне
  ~8–15 мин — неприемлемо для register/transfer.
- TargetHard = 0x0000FFFFFFFFFFFF (~2^48): 65536 итераций Argon2id
  32 МиБ ≈ 33 мин на хосте — неприемлемо для ежемесячного выпуска.

## Решение №9 (утверждено пользователем 19.10.2026; закреплено в TestGenesis)

- TargetLight = 0x0000010000000000 (2^24): ~0,6 с хост, ~1–4 с телефон
  (эмулятор без аппаратного SHA — 8,6 с).
- TargetHard = 0x0040000000000000 (2^56, ~64 итерации Argon2id):
  ~4,8 с хост (32 МиБ; замер при 2^57 — 9,5 с, линейно по таргету),
  ~4,4 с эмулятор, ~10–20 с телефон — «под средний телефон» (7.6).
- Argon2id: 32 МиБ × 1 итерация × p=1 (64 МиБ — запас для будущих сетей
  с device_policy STRICT; на телефоне 64 МиБ ≈ вдвое дороже).
- Экономика: выпуск раз в месяц → 10–20 с PoW приемлемы; register —
  разово; transfer — лёгкий PoW 2^24 ≈ 1–4 с.
