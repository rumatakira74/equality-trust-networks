# 3. Таблицы проверки транзакций

Источник: разделы 6–11, 17.
Каждый узел проверяет каждую транзакцию одинаково и независимо (7.5, 9.3).
«Принять» = транзакция попадает в журнал и учитывается при пересчёте
состояния; «Отклонить» = игнорируется с кодом `E_*` (spec/00, раздел 0.4).
Порядок проверок: общие (3.1) → по типу (3.2+) → эффекты.

Обозначения: `σ` — состояние узла; `net_time` — сетевое время текущей эпохи;
`epoch` — номер текущей эпохи; `P(w)` — личный порог отложенного перевода
кошелька `w`.

## 3.1. Общие проверки (все типы)

| # | Условие | Принять/отклонить |
| --- | --- | --- |
| C1 | `network_id` совпадает с сетью узла | иначе `E_NET` |
| C2 | `protocol_version` поддерживается узлом | иначе `E_VER` |
| C3 | `txid` неизвестен (нет дубля) | иначе `E_DUP` |
| C4 | `type` совпадает с активной веткой `payload` | иначе `E_TYPE` |
| C5 | Кошелёк `wallet` зарегистрирован (кроме `REGISTER`) | иначе `E_UNKNOWN_WALLET` |
| C6 | `seq = last_seq(wallet) + 1`; для `REGISTER`: `seq = 1` | иначе `E_SEQ` |
| C7 | `prev = txid` последней транзакции цепочки; для `REGISTER`: `prev = 0^32` | иначе `E_PREV` |
| C8 | Подпись ECDSA P-256 верна над `signing_hash` | иначе `E_SIG` |
| C9 | `|timestamp_claim − net_time| ≤ 1800` (±30 мин, 9.2) | иначе `E_TIME` |
| C10 | PoW: `POW_LIGHT` для всех типов, кроме `REGISTER`/`MINT`; сходится против таргета из `pow_params` | иначе `E_POW_LIGHT` |
| C11 | Для `REGISTER`/`MINT`: `POW_ARGON2ID`, сходится, для `MINT` — сетевое время в окне ±48 ч слота челленджа | иначе `E_POW_HARD` |

Замечание об эквивокации: две транзакции с одним `seq` обе проходят C1–C11
по отдельности — это не ошибка валидации, а конфликт, разрешаемый
финализацией (9.1); доказательство — `EVIDENCE` (3.8).

| # | Условие | Принять/отклонить |
| --- | --- | --- |
| V1 | Поручитель `active` | иначе `E_VOUCH_STATUS` |
| V2 | Возраст поручителя ≥ 3 мес. (`voucher_min_age_days = 90`) | иначе `E_VOUCH_AGE` |
| V3 | ≥ 2 выполненных периодов выпуска (`voucher_min_mint_periods`) | иначе `E_VOUCH_PERIODS` |

| V5 | `candidate ≠ wallet` (нет самомупоручительства) | иначе `E_VOUCH_SELF` |
| V6 | Кандидат в статусе `registered` | иначе `E_VOUCH_CANDIDATE` |
| V7 | Нет прежнего `vouch` от этого поручителя этому кандидату | иначе `E_VOUCH_DUP` |

→ `active`, `activated_epoch = epoch`; активирующее множество поручителей
фиксируется (для доли R). Слоты — машина состояний в spec/06.

## 3.4. `MINT` (10.1, 7.6)

| # | Условие | Принять/отклонить |
| --- | --- | --- |
| M1 | Статус `active` (10.1) | иначе `E_STATUS` |
| M2 | Нет действующей приостановки выпуска (`flagged`- suspension, 7.5) | иначе `E_FLAGGED_MINT` |
| M3 | `period > last_claimed_period` (строго, 10.1) | иначе `E_MINT_DOUBLE` |
| M4 | `period ≤ текущий_период − 1` (заявляются только завершённые периоды) и `period ≥ период_активации` (без ретро-начислений, 10.1) | иначе `E_MINT_PERIOD` (PENDING: вопрос №24) |
| M5 | `period − last_claimed_period ≤ accrual_window` (6 мес. по умолчанию; сверх окна — сгорает, 10.1) | иначе `E_ACCRUAL_WINDOW` |
| M6 | `amount = issuance_amount × (period − last_claimed_period)` | иначе `E_MINT_AMOUNT` |
| M7 | PoW усиленный, слот `H(address ‖ period ‖ checkpoint_hash(prev_epoch))`, сетевое время в окне ±48 ч (7.6) | иначе `E_POW_HARD` |

**Эффекты (принять):** для каждого заявленного периода `p` с номером выпуска
`i = p − activated_period + 1 ≤ 12` (первые 12 выпусков, 7.4):

```
доля_R = amount × voucher_reward_micros / 1e6        // 10% = 100000 micros
кошельку:   balance += amount − доля_R               // 90% в первый год
поручителям: каждому из активирующего множества — доля_R / K
```

- Источник доли — выпуск самого поручаемого; суммарная эмиссия не растёт (7.4).
- Выплата прекращается с эпохи финализации `EVIDENCE` против поручаемого (7.5).
- Офлайн-конфликт дублей: побеждает первая по порядку финализации; вторая
  аннулируется (10.1).
- Пропущенный челлендж: начисление переносится в пределах `accrual_window`,
  средства не блокируются (7.6).

## 3.5. `TRANSFER` (10.2, 7.6, 8.3)

### 3.5.1. `send`

| # | Условие | Принять/отклонить |
| --- | --- | --- |
| T1 | `transfer_mode ≠ SOULBOUND` (единица передаётся) | иначе `E_TRANSFER_MODE` |
| T2 | `transfer_mode = RESTRICTED` ⇒ `recipient ∈ providers` (только поставщику ресурса или по списку, раздел 4) | иначе `E_TRANSFER_RECIPIENT` |
| T3 | Мораторий: `net_time − register_time(w) ≥ transfer_moratorium_days` (7–30 дней, 7.6). Статус не снимает мораторий: он считается от `register` | иначе `E_MORATORIUM` |
| T4 | Эффективный баланс (после демереджа, 3.10) ≥ `amount + fee`, где `fee = max(fee_min, rate_epoch × amount)` | иначе `E_BALANCE` |
| T5 | `fee_mode = BURN` ⇒ комиссия сжигается; `POOL` ⇒ в общий фонд; `NONE` ⇒ fee = 0 (10.2) | принять |
| T6 | `amount > P(w)` ⇒ перевод становится `pending` до `net_time + 48 ч`; малые — без задержки (8.3) | принять как `pending` |
| T7 | Правило действует только при `transfer_mode = FREE` и `sandbox = false`; для `soulbound`, `restricted` и квот не применяется (8.3) | принять без задержки |
| T8 | Свежевыпущенные средства переводимы не сразу (10.1): выпуск периода t переводим с t + `fresh_transfer_window_periods` (по умолчанию 3 мес. — закрыто данными этапа 1.2, equality-anti-farm-simulation/Mistral/REPORT.md, раздел 5). Реализация пер-юнит: когорты выпусков по периодам; списание сначала из старейших переводимых когорт; расходуемый остаток = сумма переводимых когорт (сверяется в T4) | иначе `E_BALANCE` (недостаточно переводимого остатка) |

**Эффекты:** `pending` — сумма резервируется (`balance_locked += amount + fee`);
исполнение по финализации после 48 ч без отмены: получателю `amount`,
`fee` сжигается/в пул. Получатель видит «ожидает исполнения» (8.3).
Bluetooth-платёж крупнее порога подчиняется той же задержке (8.3).

### 3.6.2. Исполнение (по истечении 14 дней без отмены)

- Переносятся: возраст, история выпусков, `last_claimed_period`, поручительства
  (иначе миграция обходит мораторий и лимиты, 11); новый кошелёк получает
  статус `active`.
- Старый фингерпринт навсегда в чёрном списке (иначе цикл «миграция →
  регистрация заново» даёт бесконечные единицы, 11); старый адрес терминален.
- Награда публичным гардианам: фиксированная сумма из новой эмиссии, только
  подписавшим, только после задержки без отмены; не чаще раза в 12 мес. на
  подопечного (11). Размер — PENDING: вопрос №29.

## 3.7. `EVIDENCE` (7.5)

| # | Условие | Принять/отклонить |
| --- | --- | --- |
| E1 | Обе подписи `tx_a`, `tx_b` верны | иначе `E_EVIDENCE_SIG` |
| E2 | `tx_a.wallet = tx_b.wallet` | иначе `E_EVIDENCE_WALLET` |
| E3 | `tx_a.seq = tx_b.seq` (или `tx_a.prev = tx_b.prev`) | иначе `E_EVIDENCE_SEQ` |
| E4 | `txid(tx_a) ≠ txid(tx_b)` (хеши разные) | иначе `E_EVIDENCE_HASH` |
| E5 | Обе транзакции позже `register` (seq ≥ 2) | иначе `E_EVIDENCE_REG` |
| E6 | `kind = DOUBLE_MINT` ⇒ обе — `MINT` одного `period` | иначе `E_EVIDENCE_KIND` |
| E7 | Факт `(wallet, seq)` не доказан ранее | иначе `E_EVIDENCE_DUP` |

Никто не выносит решение: доказательство подаёт любой узел, проверяют все
одинаково и независимо; проверка не зависит от времени и порядка прихода (7.5).
Закрытый перечень: только эквивокация и двойной выпуск; «похож на ферму»
доказательством не является (7.5).

**Эффекты (принять; мягкая схема, 7.5 — PENDING: вопрос №5):**

1. Кошелёк получает постоянную публичную метку `flagged` (не снимается).
2. Обе конфликтующие ветки не принимаются; остаётся ветка, выбранная
   финализацией (9.1).
3. Выпуск приостанавливается на N месяцев (N — PENDING: вопрос №12); при
   повторе — навсегда.
4. Поручители перестают получать долю R от выпуска этого кошелька (с эпохи
   финализации).
5. Денежных штрафов и потери слотов нет; награды за подачу доказательства нет
   (иначе ферма подаёт доказательства на свои же кошельки, 7.5).

## 3.10. Демередж (10.3) — применяется при любой расходующей операции

Транзакций списания нет; эффективный остаток вычисляется детерминированно
при следующей операции кошелька по числу прошедших эпох `n`:

```
balance_eff = floor + (balance − floor) × (1 − rate)^n    при balance > floor
balance_eff = balance                                     при balance ≤ floor
```

- `rate` = `demurrage_rate_micros / 1e6` в месяц; `floor` = `demurrage_floor`;
  списанное сжигается (10.3).
- Выключен по умолчанию; в профилях 5 и 7 включён (10.3). Значения — этап 1.2.
- `n` — число эпох с последней операции, менявшей баланс (или с включения
  демереджа). Точка привязки `n` — PENDING: вопрос №31. Применимость демереджа
  к `pending`-резерву отложенного перевода — PENDING: вопрос №18.

| K4 | confirm | Лимит подтверждений на человека в период не исчерпан | иначе `E_CONTRIBUTION_LIMIT` |
| K5 | confirm | Этот подтверждающий ещё не подтверждал эту заявку | иначе `E_CONTRIBUTION_DUP` |
| K6 | confirm | Ролей координатора нет; N независимых подтверждений принимают заявку (N — PENDING: вопрос №13) | принять |

**Эффекты:** подтверждённая заявка выплачивается из пула программы
(рекомендуется, инфляции нет) либо ограниченной эмиссией `on_contribution`
с потолком на период и на человека (6.4; потолки — PENDING: вопрос №13).
Риск сговора смягчается лимитами, потолком, графом и публичностью, но полностью
не устраняется (6.4).
