# 5. Тестовые векторы

Каталог `vectors/`; формат описан в `vectors/README.md`.

## 5.1. Назначение

Векторы — фиксированные точки оракула проверки из spec/03: для каждой
транзакции заданы полное состояние сети (параметры + pre_state) и ожидаемый
результат (`accept`/`reject` + код `E_*` + эффекты). Этап 3 использует их
как приёмочные тесты ядра; этап 2 материализует криптографические поля
(подписи, PoW, хеши) эталонной реализацией.

## 5.2. Что материализуется на этапе 2

В v1-draft подписи, PoW-nonce и хеши — плейсхолдеры (`SIG_PLACEHOLDER`,
`POW_NONCE_PLACEHOLDER`, `txid:WALLET:seq`), потому что этап 0 не реализует
код протокола. Всё остальное (поля, состояние, ожидаемые коды, арифметика
балансов) — конкретно и машиночитаемо сразу. Правило: вектор считается
пройденным, если ядро выдаёт ожидаемый код `OK`/`E_*` для каждой транзакции
и ожидаемые пост-эффекты.

## 5.3. Перечень векторов

### Валидные (по одному на каждый тип, раздел 9.3)

| Файл | Тип | Проверяемые правила |
| --- | --- | --- |
| `valid_register.json` | REGISTER | аттестация, фингерпринт, усиленный PoW, гардианы |
| `valid_vouch.json` | VOUCH | 3-е поручительство → активация кандидата; слоты, возраст |
| `valid_mint.json` | MINT | первый выпуск, окно накопления (нагон 3 мес.), доля R поручителям |
| `valid_transfer.json` | TRANSFER/send | комиссия сжигается, мораторий пройден, лёгкий PoW |
| `valid_migrate.json` | MIGRATE/propose | 2 из 3 личных гардианов, задержка 14 дней |
| `valid_evidence.json` | EVIDENCE | валидное доказательство эквивокации → `flagged` |
| `valid_guardian_offer.json` | GUARDIAN_OFFER | active ≥ 12 мес. |
| `valid_pool_create.json` | POOL_CREATE | параметры пула |
| `valid_pool_donate.json` | POOL_DONATE | донат в открытый пул |
| `valid_pool_close.json` | POOL_CLOSE | закрытие после дедлайна |
| `valid_pool_claim.json` | POOL_CLAIM | равная доля active-кошельку |
| `valid_redeem.json` | REDEEM | погашение у поставщика из параметров |
| `valid_receipt.json` | RECEIPT | подтверждение погашения поставщиком |
| `valid_contribution_claim.json` | CONTRIBUTION_CLAIM | заявка вклада |
| `valid_contribution_confirm.json` | CONTRIBUTION_CONFIRM | подтверждение peer |

### Негативные и потоковые

| Файл | Сценарий | Ожидание |
| --- | --- | --- |
| `bad_equivocation.json` | два `TRANSFER` с одним `seq` разным получателям; `EVIDENCE` на них | конфликтные ветки; evidence принята → `flagged`, выпуск приостановлен |
| `bad_double_mint.json` | два `MINT` одного `period` | второй: `E_MINT_DOUBLE`; evidence DOUBLE_MINT принята |
| `bad_moratorium.json` | `TRANSFER` на 3-й день после `register` (мораторий 7) | `E_MORATORIUM` |
| `bad_accrual_window.json` | `MINT` с пропуском 7 мес. (окно 6) | `E_ACCRUAL_WINDOW` |
| `flow_delayed_cancel.json` | крупный перевод (> P) → `pending`; отмена через 10 ч | перевод отменён, резерв возвращен; исполнения нет |

## 5.4. Правила поддержки

- Каждое изменение таблиц spec/03 обязано сопровождаться пересборкой
  затронутых векторов; вектор без ссылки на правило — ошибка.
- Векторы фиксируют локальные значения параметров (fee, P, rate) — глобально
  эти значения остаются «этап 1.2».
- Отдельная категория — синтетические векторы аттестации (этап 2):
  реальные и синтетические цепочки X.509 для проверки разбора (этап 2 плана).
