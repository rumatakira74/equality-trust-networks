# REPORT-stage3.md — этап 3: ядро реестра на Go (без сети)

Ветка `stage3-core`. Источники: spec/ + proto/ + vectors/ + QUESTIONS.md
(этап 0), equality-anti-farm-simulation/Mistral/REPORT.md (значения 1.2). Подэтап 3.0
(криптофундамент этапа 2) выполнен здесь, т.к. в репозиториях отсутствовал.

## 1. Что сделано

### 3.0. Криптофундамент

| Пакет | Содержание |
| --- | --- |
| `core/wire` | Canonical-кодек protobuf (поля в порядке номеров, unknown-поля запрещены, proto3-правило нулей), конверт `Transaction`, `signing_hash = SHA-256(preimage ‖ pow.nonce)`, `txid = SHA-256(canonical(tx))` (spec/01 1.2); StateLeaf (9 полей, D7), Checkpoint, MigrateStatement; ProfileParams/Manifest/Genesis с manifest_hash |
| `core/crypto` | ECDSA P-256 подпись/верификация (DER, ручной разбор без stdlib-ASN.1-подписи), `walletFingerprint = SHA-256(pub ‖ protocol_id)`, лёгкий PoW (SHA-256), усиленный Argon2id (`x/crypto/argon2`), деривация адреса — заменяемая функция (PENDING №2) |
| `core/attest` | Разбор цепочки X.509 (`encoding/asn1` + `crypto/x509`), проверка: аппаратный уровень, `verifiedBootState = Verified`, `deviceLocked`, свежесть уровня патча; синтетические корни/листы для тестов (реальные корни Google — этап 6); формула `attestation_challenge` — параметризуемая (PENDING №23) |
| `core/smt` | Sparse Merkle глубины 256: корень, доказательства, верификация |
| `core/threshold` | N-из-M набор подписей ECDSA P-256 (решение этапа 0): дедупликация подписантов, учёт только участников набора |

### 3.1. Хранилище

`core/store`: SQLite через pure-Go `modernc.org/sqlite` (без CGo): таблица
транзакций (canonical-байты, каузальный порядок вставки — для replay),
индекс «фингерпринт → адрес», чёрный список фингерпринтов, заголовки
чекпоинтов (интерфейс этапа 5), meta. Replay из журнала детерминирован —
проверен тестом INV-3 (`TestReplayFromStore`).

### 3.2. Валидация и применение

`core/ledger`: порядок проверок строго по spec/03 — C1–C11 → типовые
таблицы (R1–R7, V1–V9, M1–M7, T1–T8, X1–X4, S1–S2, G1–G5, N1–N2, E1–E7,
O1–O2) → эффекты; каждый отказ — точный код `E_*` из spec/00 0.4.
Все типы ядра: REGISTER, VOUCH, MINT, TRANSFER (send/cancel/set_threshold),
MIGRATE (propose/cancel), EVIDENCE, GUARDIAN_OFFER. Модульные типы не
реализованы (этап 10), структура им не мешает (payload 17–24 зарезервированы).

Эквивокация — не ошибка валидации: ветка на той же высоте (seq == last_seq,
другой txid) проходит C8–C11 и уходит в `Conflicts` финализатору
(интерфейс `Finalizer`; headless-заглушка FirstWins). EVIDENCE — по E1–E7,
последствия мягкой схемы: постоянный `flagged`, приостановка выпуска
(N = 3 мес. локально, вопрос №12), доля R = 0, штрафов и потери слотов нет.

### 3.3. Сеттлемент (детерминированный)

На границе эпохи: истечение `registered` (3 года), освобождение слотов
(3 периода выпуска / 90 дней), `seed_sunset`. На границе периода: демередж
`burn = floor((balance − floor) × rate / 10⁶)`, сгорает, pending-резерв не
демереджится (№18). По срокам (flush перед каждой операцией): исполнение
pending-переводов через 48 ч без отмены, миграций через 14 дней (перенос
статуса, истории, поручительств; старый фингерпринт — навсегда в чёрный
список), повышение P через 48 ч. Окно переводимости — пер-юнит когорты
выпусков, списание из старейших переводимых (T8, вопрос №11 закрыт).

### 3.4. Параметры

`core/params`: значения по умолчанию тестового genesis — из REPORT 1.2
(демередж 1 %/3000; комиссия fee_min 1, [0,5 %; 2 %], старт 1 %, BURN; окно
3 мес.; мораторий 14 дней; P 3000/P_max 30000) и зафиксированные 1.1 (K = 3,
слоты 3/5/10, R = 10 %, посев ≥ 300 — не тронуты). В коде всё читается из
манифеста, ничего не зашито.

### 3.5. Тесты

- **Векторы (12/12 зелёные)**: valid_register/vouch/mint/transfer/migrate/
  evidence/guardian_offer, bad_equivocation/double_mint/moratorium/
  accrual_window, flow_delayed_cancel. Проверяются исход + код `E_*` +
  пост-эффекты (балансы, статусы, метки, слоты, pending-операции).
- **Property**: 400 случайных операций (переводы, выпуски, эквивокации,
  pending, guardian_offer, невалидные мутации) — INV-проверки после каждого
  шага, FullCheck на границах эпох. Метаморфный тест: 7 мутаций, каждая
  даёт ровно свой код.
- **Сквозной сценарий**: register → vouch×3 → mint (R-доля 33×3+1) →
  отказ перевода свежего выпуска (окно 3 мес.) → перевод после созревания →
  отложенный > P → исполнение по сроку → эквивокация + evidence → migrate
  (2 из 3 гардианов, исполнение через 14 дней, чёрный список). INV-8 на
  каждом шаге.
- **Сеттлемент**: демередж (в т.ч. ниже floor), истечение, слоты,
  seed_sunset, повышение P.
- **Крипто**: подписи DER (валидная/битая/чужой ключ), PoW лёгкий и
  Argon2id, деривация адреса, canonical-кодек (round-trip, unknown-поля,
  стабильность хешей), аттестация (валидная + 4 тампера), N-из-M
  (3/5, 2/5, посторонний, дубликат), sparse Merkle (root/prove/verify).

## 3. Отклонения от спецификации и противоречия (не молча)

| № | Отклонение | Причина |
| --- | --- | --- |
| D-1 | Проверка окна слота челленджа M7 (±48 ч) вынесена в `CheckMintChallengeWindow` и в headless-ядре отключается опцией `SkipMintChallengeWindow` | векторы этапа 0 (обязательный регресс) не моделируют слот: их времена произвольны и попали бы вне ±48 ч случайного слота. Проверка реализована и покрыта кодом; включается в продакшене (этап 5 даст расписание чекпоинтов) |
| D-2 | Демередж материализуется на границе ПЕРИОДА (месяца), не эпохи | spec/03 3.10 говорит «эпохи», но ставка задана «в месяц» (10.3); при суточных эпохах (тестовый genesis) буквальное прочтение противоречило бы ставке. Якорь периода сохраняет семантику `(1−rate)^n` |
| V-1 | `vectors/valid_mint.json`: в pre_state добавлены `vouch_count: 3` и `activators: [W_V1..W_V3]` | вектор был внутренне неполон: effects требуют R-долю поручителям, а активирующее множество не было задано. Правка данных, не правил |
| I-1 | Баланс переносится при миграции | spec/03 3.6.2 баланс не называет, но перенос следует из назначения миграции (иначе она равна перезапуску, где «средства теряются», 11). Также переносятся занятые слоты — иначе миграция обходит лимиты |
| I-2 | R-остаток деления (1 ед. при 100/3) достаётся майнящему; демередж — целочисленный `floor` | детерминизм: все узлы обязаны сходиться в байтах; правило остатка в Документе не задано |
