# Тема Фиксы F5 и F16 — продолжение: эмуляторный прогон приманки (F5)

Ветка `fix-f5-f16` (tip `adc1b67`, origin в актуальном состоянии) содержит полную реализацию
F5 и F16, все тесты и headless-доказательство eclipse. Единственный остаток темы —
эмуляторный прогон приманки (пункты mandate п.4/п.1, раздел (а) отчёта). Источник истины
по сделанному и по всем техническим приёмам — `reports/REPORT-FIX-F5-F16.md`, разделы (б)
и (в). Прочитать их ДО начала работы и следовать буквально.

## Шаг 0 — сверка живого состояния (правило после паузы/рестарта сессии)

Свежий fetch ветки `fix-f5-f16`. Живое состояние против `adc1b67`: рабочее дерево чистое,
незакоммиченных файлов нет. Любое расхождение — стоп, зафиксировать расхождение в отчёт,
спросить владельца. Незаккоммиченные находки предыдущей сессии (если обнаружатся) — не
затирать, а показать владельцу.

## Мандат (только эмуляторный прогон — код не трогать)

1. Эмуляторный прогон приманки строго по разделу (б).1 отчёта:
   - AVD `stage12ga`, запускать с `-gpu host` (swiftshader/TCG/`-gpu off` падают SIGSEGV);
   - пиры песочницы — бинарь amd64, запуск detached на портах 4001/4002 с peer ID из (б).1
     (peer1 QmNPJien…, peer2 QmNXG1JR…), инструкции сборки в (б).1;
   - APK: `flutter build apk --debug`, AAR — `gomobile bind` с
     `GOFLAGS=-ldflags=-checklinkname=0` (см. (б).1), `adb install -r`, `pm clear`;
   - enroll отпечатка по (б).1 (`adb -s emulator-5554 emu finger touch 1`, проверка
     `dumpsys fingerprint | grep prints` → `id:0`; если app не видит — force-stop и
     перезапуск);
   - сценарий: онбординг (PIN 1234, тревожный 9876, легенда 100) → регистрация кошелька →
     вход тревожным PIN → скриншоты кошелька и карточки восстановления (подменной адрес) →
     `adb logcat` за прогон не содержит реального адреса → выход обычным PIN → реальный
     адрес на месте.
2. Артефакты → `reports/fix-f5-f16/emu/` (скриншоты PNG + logcat-выжимка `.txt`, не `.log`;
   каждый файл ≤1 МБ).
3. Дописать результаты в `reports/REPORT-FIX-F5-F16.md`: раздел (а) пункт 1 → ✅
   (эмуляторный прогон), ссылки на артефакты; в разделе (б).1 обновить состояние отпечатка
   по факту.
4. FINDING при расхождении поведения прогона с кодом/README 8.2 — в раздел (г) отчёта +
   стоп-вопрос владельцу; самовольно не чинить. Код, тесты, спека, README и
   `reports/REPORT-AUDIT-FRONTIER-PASS.md` (F5/F16 уже «Решено») — не трогать.

## Правила

- Событийные коммиты с session-ID; промежуточный чекпоинт-коммит раз в ~30 мин.
- Вес-правило: каждый файл ≤1 МБ.
- Уборка в конце: qemu/java/tnp-node/tnp-testnet/sandbox-peer/gradle — 0 процессов,
  `adb devices` пуст, временные файлы вне репо удалить, worktree вычистить.
- Финал: пуш ветки `fix-f5-f16` + «CI pending» (номера прогонов); статусы CI не ждать.
- Merge — только после зелёного CI-verify (`prompts/ci-verify-prompt.md`) и подтверждения
  владельца. Не мержить самому.

## Критерий готовности

Эмуляторный прогон закрыт артефактами в `reports/fix-f5-f16/emu/`, отчёт дополнен
(пункт (а).1 → ✅), ветка запушена, «CI pending», рабочее дерево чистое, процессов нет.
