# Промпт фикс-темы fix-cp-threshold — C1 аудита Sonnet-2: подделка чекпоинта

Ветка: `fix-cp-threshold` от свежего `main` (рабочий клон /home/projects/audit-equality-trust-networks; личный клон не трогать; префикс `audit*` запрещён). Тема кодовая, консенсусная: закрыть C1 — критичную находку аудита Sonnet-2.

Источник: дайджест reports/DIGEST-AUDIT-SONNET-2.md в main; полный отчёт: git show origin/audit-sonnet:reports/audit-sonnet/REPORT-AUDIT-SONNET-2.md (секции про чекпоинты); готовые красные тесты: git show origin/audit-sonnet:reports/audit-sonnet/go-tests/ (файлы с cpforgefix в имени) — выписать их содержимое и включить в пакет тестов.

Долг (C1): Verify принимает Participants/Threshold из самого чекпоинта (Threshold=0 проходит без единой подписи); принимающая сторона не сверяет состав/порог с манифестом; подписант подписывает любое предложение эпохи, не сверяя StateRoot со своим реестром. Итог: чужой StateRoot/TotalSupply/FinalizedTxIDs → выбор ветки эквивокации (двойная трата).

Шаги (минимальный план аудита):
1. Принимающая сторона: сверять cp.Participants и Threshold с cons.Participants(...) по режиму манифеста; Threshold == 0 — отвергать.
2. Подписант: подписывать предложение только при совпадении StateRoot со своим реестром.
3. Проверка «эпоха наступила» и принадлежность предложения строителю эпохи.
4. Валидатор темы чекпоинтов.
Консенсус-правило меняется — оформление по образцу 3.2 отчёта (поле манифеста/версия), обратная совместимость: сети с прежними манифестами работают.

Тесты: cpforgefix из go-tests — красные на входе, зелёные после фикса; go build ./... rc=0; go test ./... зелёные; go test -race ./cons/ зелёные. Регресс: валидные чекпоинты существующих тестов не отвергаются.

Отчёт: reports/REPORT-FIX-CP-THRESHOLD.md на ветке: план, file:line, результаты прогонов, session-ID.

Правила: чекпоинты событийные + ~60 мин (session-ID), чистое дерево, пуш ветки, НЕ мержить. Модель и окно — YAML-шапкой задачи очереди.
