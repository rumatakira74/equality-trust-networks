# Диагностический прогон r2-check — без изменений в репозитории

**Предусловие:** это диагностика, НЕ тема конвейера. Репозиторий read-only: никаких коммитов, правок, веток, пушей. Секреты (api-ключи, токены, пароли) не выводить ни в каком виде — если встречаются в файлах, НЕ печатать их, писать только «секрет присутствует, скрыт».

## Задачи (все — сбор фактов и вывод краткой сводки)

### 1. Причина .failed задачи A8 (00000003)
- Прочитать хвост файла `/home/projects/mistral-harness-workflows/cli-jobs/logs/launcher.log` (последние 80 строк; если файла нет — записать это).
- Если существует `/home/projects/mistral-harness-workflows/cli-jobs/logs/00000003-a8-keys.log` — прочитать и его хвост.
- Выписать ТОЧНЫЕ строки с причиной отказа задачи 00000003 (стадия предзапускных проверок или ошибка сессии).

### 2. Модели CLI
- Прочитать `~/.vibe/config.toml`. Вывести ТОЛЬКО список имён моделей из блоков `[[models]]` (поле name) и их thinking_levels, если заданы. Секреты и api-ключи НЕ выводить. Отметить, есть ли в списке `zai-glm-5-3`.

### 3. Ресурсы машины
- `free -m` и `uptime` — свободная память (лаунчер требует ≥2 ГБ свободной), загрузка.

### 4. Тест wrangler ↔ R2 (бакет tnp-artifacts)
Выполнять по очереди; при ошибке любой команды — записать её точный текст и продолжить со следующей (диагностика НЕ падает из-за облака):
- `wrangler --version`
- `wrangler whoami` (аккаунт; если выводит email — допустимо)
- `wrangler r2 bucket list` — показать, есть ли `tnp-artifacts`
- PUT: создать локальный файл `/tmp/r2-check-cli.txt` (одна строка: текущая дата-время и метка «r2-check from CLI session»), затем `wrangler r2 object put tnp-artifacts/r2-check/2026-11-03-cli.txt --file /tmp/r2-check-cli.txt`
- GET: `wrangler r2 object get tnp-artifacts/r2-check/2026-11-03-cli.txt --file /tmp/r2-check-cli-download.txt`, сверить содержимое с исходным (diff или сравнение строк)
- DELETE тестового объекта из R2: `wrangler r2 object delete tnp-artifacts/r2-check/2026-11-03-cli.txt` (при запросе подтверждения — флаг `--force`, если он есть в подсказке команды); после — убедиться, что локальные /tmp/r2-check-cli*.txt удалены
- Итог по R2: put/get/delete — успех или точные ошибки на каждом шаге

## Правила
- Ничего не менять в репозиториях и в ~/.tnp-signing/ (если существует).
- Долгих прогонов нет; всё должно занять минуты.
- Стоп-вопросы не задавать; при блокере — записать его в сводку и продолжить остальные пункты.
- В конце — ТОЛЬКО сводка: (1) причина .failed A8 — цитата; (2) список alias моделей; (3) память; (4) R2 put/get/delete — статус по шагам. Без вопросов.
