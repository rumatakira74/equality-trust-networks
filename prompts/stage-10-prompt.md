## Задача

1. **Адаптивная комиссия (долг 8.0, закрывает заглушку `Fee = RateMin`):** детерминированный пересчёт `rate` на границе эпохи из данных чекпоинтов (раздел 10.2 спеки; rate ∈ [0.5; 2]%) — без координации, все узлы сходятся к одному значению; тесты эквивалентности пересчёта (одинаковое значение на всех узлах, пограничные случаи, рестарт из БД).
2. **`attest` + проверяющая библиотека (Go; сборки JVM и JS — вопрос 15):** подпись кошелька, Merkle-доказательство из чекпоинта, `challenge`, срок годности, `H(address ‖ app_id)`; лёгкий клиент-синхронизатор (проверка предъявления без полного узла). Критерий плана: верификатор проверяет предъявление в стороннем приложении.
3. **`redeem`:** погашение с `resource_id`, квоты `quota_reset`, подписанные `receipt`.
4. **`pool`:** `pool_create/donate/close/claim`, режимы выпуска, возврат.
5. **`contribution`:** `contribution_claim/confirm`, подтверждения `peer`, лимиты, потолки, выплата из пула.
6. **`sandbox`:** синтетические кошельки, headless-режим, экспорт реестра для анализа.
7. **Конфигуратор сети (на базе `cmd/tnp-testnet`):** выбор шаблона профиля, параметры, genesis-пакет + приложение, вычисление уровня гарантий из манифеста (раздел 3.3). Критерий плана: организатор без программирования создаёт сеть-инстанс по шаблону.
8. **Шаблоны семи профилей (раздел 5) и их валидация** (например, запрет `relaxed` при высоких ставках).
9. **Локализация UI кошелька (i18n, Flutter):** кандидаты — ru, en, es, pt, fr, de, it, zh, ja, fa, he; **состав языков — решение владельца (PENDING, вопрос в `QUESTIONS.md`), не ждать блоком: готовить ru + en полностью** (fallback — английский), остальные подключать по мере решения. Реализация: `flutter_localizations` + `intl` (ARB-каталоги), вынос всех строк из кода; фарси и иврит — RTL-разметка (`Directionality`, зеркальные направленные ассеты); выбор языка в настройках; приоритет — языки сообществ первых пилотов (этап 11, порядок раздела 16.4).

## Правила

1. Источники: спека `docs/KNOWLEDGE.md`, `spec/`, отчёты этапов 3–9, `QUESTIONS.md`. Ничего не додумывать: механизма нет — PENDING с номером вопроса в `QUESTIONS.md`.
2. Модули — типизированные операции в Go-ядре, **не смарт-контракты и не токены**; изменения протокола — только там, где этого прямо требует спека; редактирование `docs/KNOWLEDGE.md` — отдельными коммитами, bump версии (v9.7) и только формализация уже реализованного.
3. Вся работа — в ветке **`stage10-profiles`** (шаг 0). Пуш ветки и merge в `main` — только после подтверждения владельца (сначала пуш ветки, затем merge).
4. **Промежуточные коммиты (событийные + временные):** после каждого завершённого пункта задачи, цикла тестов или прогона — прогресс-коммит (артефакты, логи, прогресс-файл, session-ID в сообщении коммита). Внутри длинного пункта сверять метки времени в выводах инструментов: накопилось ~30 минут активной работы — коммит промежуточного состояния, даже если пункт не завершён. Часы между операциями не отслеживать «по ощущению» — только по меткам в выводах. Чекпоинты содержат WIP-код и рабочие артефакты, но не бинарники и не scratch-мусор: перед add проверять `git status`, крупные временные файлы держать вне репо (/tmp); финальный коммит этапа оставляет чистое дерево, история не переписывается. После любого рестарта сессии (краш, `--continue`, новая сессия) — до любых действий сверить живое состояние с последним коммитом ветки и отчитаться планом; ничего не перезапускать и не повторять без сверки.
5. Коммитить по пунктам задачи, осмысленные сообщения. Приватные данные (ключи, seed-фразы, номера телефонов) в репозиторий не попадают.
6. Имена файлов английские; комментарии в коде русские.
7. Тесты и уборка: `go test ./...` и `-race` (core, cons, net, mobile), `flutter analyze`/`test`, CI зелёные. Прогоны локальные; после каждого прогона — остановить Gradle-демоны, завершить `tnp-node`/`tnp-testnet`/`qemu`; перед следующим прогоном проверить `pgrep`.
8. Флак: `TestSideChannelPublishPropagates` (net) может падать по таймауту при работающих эмуляторах — перезапустить без эмулятора, не считать регрессом без повтора.
