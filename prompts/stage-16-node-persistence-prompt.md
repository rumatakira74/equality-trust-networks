# Этап 16 — персистентность узла приложения (№38: SQLite/SIGSYS на Android, ветка stage16-node-persistence)

**Предусловие:** этап 15 слит (merge `cdb910d`), CI ветки этапа 15 зелёный по всем 8 jobs пяти workflows. Запуск — по команде владельца (дана). Ветка `stage16-node-persistence` — от свежего `main`. Основание: №38 QUESTIONS.md (modernc.org/sqlite — pure-Go — вызывает libc через `Xlstat` → raw `SYS_LSTAT`; app-seccomp эмуляторов API 35/36 не разрешает этот сисколл → SIGSYS; узел приложения работает в памяти, `NodeController.inMemoryDb`) и находка аудита: узел приложения хранит всё в памяти — баланс и история теряются при каждом рестарте и зависят от доступных пиров; противоречит README 12.5, в DISCLAIMER не отражено. Порядок работ аудита, п. 4: персистентность узла — заменить SQLite-драйвер или ждать фикса upstream. Этап 15 (txNow, cons.Replay strict, сеттлемент от max(txNow)) закрыл блокер рестарта из БД (№40): store-replay детерминирован и сходится с холодной синхронизацией — персистентность больше не упирается в консенсус. Живых сетей нет. Правило CI-verify: сессия этапа НЕ ждёт статусов CI.

**Цель:** узел приложения на Android персистентен: жёсткий рестарт приложения не теряет баланс, историю и журнал, не требует полной ресинхронизации от пиров; сверка с сетью после рестарта — инкрементальная (якорь №41); SIGSYS закрыт с доказательством в эмуляторе; README и DISCLAIMER — честные.

**Задачи:**

1. **Диагноз №38 на актуальных версиях.** Обновить `modernc.org/sqlite` и `modernc.org/libc` до последних; в эмуляторе API 35/36 запустить узел с файловой БД (`inMemoryDb = false`) и проверить SIGSYS. Вердикт в отчёт: ушёл ли `Xlstat` → `SYS_LSTAT` (ссылка на upstream-коммит/issue); лог app-seccomp/tombstone приложить. Если SIGSYS на свежих версиях снят — драйвер не менять, идти дальше на modernc.

2. **Решение по драйверу (если SIGSYS остался).** Порядок предпочтения: (1) upstream-фикс modernc; (2) смена драйвера. Кандидаты: `ncruces/go-sqlite3` (pure-Go, WASM через wazero — без raw-сисколлов, seccomp-безопасен по построению) и `mattn/go-sqlite3` (cgo через NDK — быстрее на ARM, но пересборка AAR и рост бинарника). Критерии выбора: seccomp-совместимость (главный), размер AAR/APK, скорость на ARM (замер вставки/чтения журнала), риск сборки gomobile bind. Выбор и обоснование — в отчёт. Интерфейс `core/store` и схема не меняются: SQLite — реализация раздела 12.5, протокол не трогается, `protocolVersion` не поднимается.

3. **Включить персистентность узла приложения.** Файл БД — в приватном каталоге приложения; никаких внешних хранилищ. Весь файловый I/O узла — off-main (урок ANR 8.1: блокирующий старт на главном потоке запрещён; готовность узла — через колбэк). Рестарт приложения: журнал из БД → cons.Replay strict (пинирование на claim, этап 15) → инкрементальная сверка с пирами (якорь №41: первая сверка полная, дальше только новые tx). Собственный журнал не предлагается обратно gossip-ом (E_DUP-шторм 8.1 не возвращается; дедуп txid до apply). Полный/лёгкий режим узла (12.2) и переключение по условиям — не трогать.

4. **Тесты (обязательные):** (1) рестарт из БД: store-replay из БД = холодная синхронизация (эталон тестов №40/этапа 15), state_root идентичен; (2) приложение после жёсткого рестарта без пиров: баланс и история из локальной БД; после появления пира сверка доходит до сети; (3) отсутствие SIGSYS: приложение с файловой БД живёт в эмуляторе API 35/36 (лог seccomp/tombstone приложить); (4) идемпотентность сеттлемента после рестарта: повторное применение журнала не двигает демередж (монотонность от max(txNow)); (5) инкрементальный якорь после рестарта: повторная сверка не пересылает весь журнал; (6) E_DUP-шторм отсутствует.

5. **Эмуляторный прогон (артефакты в `reports/stage16/`).** Песочница по образцу этапа 7: онбординг/регистрация → выпуск/перевод → жёсткий рестарт приложения (force stop + relaunch) → баланс/история без пиров → сверка с пиром → state_root идентичен → повторный рестарт → повторная сверка инкрементальна. Сдвиг часов не требуется. Скриншоты и логи — в `reports/stage16/`.

6. **Документация.** №38 в QUESTIONS.md — статус «решено (этап 16)» с фиксацией варианта (upstream-фикс или смена драйвера); README 12.5 и DISCLAIMER.md — убрать оговорку «узел в памяти», персистентность заявлена честно; строка чек-листа 8-live про lstat/SIGSYS обновляется: проверить выбранный драйвер на живой прошивке. Спека не меняется: раздел 12.5 уже обещает SQLite-хранилище — реализация догоняет документацию.

**Предкоммитная проверка (обязательно):** `gofmt -l .` — пусто; `go vet ./...` — чисто; `go test ./...` — зелёные, по задетым пакетам `-race`; форматирование — отдельным коммитом от смысловых правок (пометка «formating only»). Dart — `flutter analyze` чисто; Kotlin — сборка модуля проходит.
