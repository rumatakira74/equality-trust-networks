Ты — zcode-агент, работаешь локально в каталоге `/home/projects/audit-equality-trust-networks` (конвейерный клон rumatakira74/equality-trust-networks). Личный клон владельца `/home/projects/equality-trust-networks` НЕ трогать.

Задача — проверка read-only по коду: собрать APK текущего main и на Android-эмуляторе проверить доступность и работу меню выбора языка интерфейса. Код приложения не менять; ветка служит только для отчёта и скриншотов.

Использовать скилл emu-run (если он установлен; шаги ниже эквивалентны ему): подготовка, запуск эмулятора, сборка/установка APK, скриншоты, уборка процессов.

## Ожидаемое состояние (сверять с фактическим main, не с этим текстом)

На момент составления мандата в main 5 языков интерфейса: ARB `app/lib/l10n/app_{ru,en,es,pt,zh}.arb`; выбор языка чипами в настройках (`app/lib/screens/settings/settings_screen.dart`, константа `languages`, подписи через ключи languageRu/En/Es/Pt/Zh/System; fallback en). Если фактический набор ARB в main на момент прогона отличается (например, добавлены fr/de/it/ja) — проверять по фактическому набору.

## Задачи

1. Подготовка: `git checkout main && git pull --ff-only`; записать SHA main; `flutter pub get`; `flutter analyze` — результат зафиксировать (нечистый analyze — FINDING, сборку продолжать, если собирается).
2. Сборка: `flutter build apk --debug` (релизную не собирать — подписание release-ключами вне мандата); записать путь и размер APK.
3. Эмулятор: проверка остатков прошлого прогона (pgrep qemu/java/tnp-node/tnp-testnet, `gradle --stop` — висящие остановить); выбрать AVD командой `emulator -list-avds` (x86_64; если подходящего AVD нет — стоп-вопрос владельцу с списком доступных); `emulator -avd <имя> -no-window`; дождаться загрузки (`adb wait-for-device`, `adb shell getprop sys.boot_completed` = 1); `adb install -r <APK>`.
4. Сценарий проверки — каждый шаг фиксировать скриншотом `reports/check-lang-menu/NN-kebab-case.png` (нумерация сквозная, имена на английском):
   (а) запуск приложения, стартовый/главный экран;
   (б) переход в настройки: пункт выбора языка присутствует и доступен;
   (в) меню языков открыто: перечень чипов соответствует фактическому набору ARB main + вариант «Системный» (System);
   (г) выбрать es — интерфейс перешёл на испанский;
   (д) выбрать System — интерфейс вернулся к языку системы эмулятора;
   (е) перезапустить приложение — выбранный язык сохранился;
   (ж) навигация назад по настройкам работает, прочие пункты настроек доступны.
   Если для доступа к настройкам нужна разблокировка/инициализация кошелька — использовать тестовый путь по прецедентам смоук-прогонов тем fix-d2-clamp / fix-d11-buffer; при блокировке (биометрия/Keystore на эмуляторе) — стоп-вопрос владельцу с описанием экрана.
5. Уборка (обязательна): `adb emu kill`, `gradle --stop`, чистка процессов и незакоммиченных бинарников сборки из корня репо.
6. Отчёт: `reports/REPORT-CHECK-LANG-MENU.md` на ветке `check-lang-menu` (от свежего main): SHA main, путь/размер APK, таблица «шаг → скриншот → результат», фактический перечень языков, вердикт («меню доступно/недоступно, переключение работает/не работает», замечания). Попутные находки — FINDING-CHECK-LANG-MENU-*.txt рядом с отчётом. Чекпоинт-коммит с session-ID в сообщении, push ветки. Merge НЕ делать; перенос отчёта в main — отдельное решение владельца.

## Ограничения и правила

- Код приложения не править; коммитить только reports/** (отчёт + скриншоты) и FINDING-*.txt; файлы > 1 МБ не коммитить (скриншоты сжать); перед add проверять git status.
- Ресурсы: не более 6 из 8 ядер; контролировать память; при < 2 ГБ свободной — стоп, зафиксировать в FINDING, стоп-вопрос владельцу.
- Часы хоста не сдвигать.
- Стоп-вопросы владельцу: нет подходящего AVD; сборка падает; доступ к настройкам блокируется; пункт выбора языка в настройках отсутствует (зафиксировать как находку, код не править).
- Лимит времени: ≤120 минут. После рестарта сессии — сверить живое состояние с последним коммитом ветки, отчитаться планом, ничего не повторять без сверки.
- Мандат выполняется самостоятельно; в конце — только сводка.
