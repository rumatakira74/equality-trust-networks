# Промпт: мини-тестнет этапа 12 — живой прогон recurring на ноутбуке

Контекст: блок мини-этапов 12.x закрыт и слит в main; спека v9.11 (`da7bd9c`). Прогон 12.2 был эмуляторным; мини-тестнет — живой прогон на ноутбуке владельца (openSUSE Tumbleweed, zram 100% RAM — новая машина после Linux Mint) на **реальном времени**: периоды и эпохи короткие, сдвиг часов хоста НЕ используется (граница периода наступает сама за минуты; sudoers-грант не нужен, timesyncd не трогать).

## Решения и рамки

1. Прогон подтверждает этап 12 на живом времени: сгорание recurring-единиц на реальной границе периода, отсутствие сгорания в std, replay-защита между сетями, рестарт узла из БД. Код не меняется (кроме критических блокеров прогона — с пометкой в отчёте).
2. Спеку не править; расхождения — в раздел отчёта «для спеки» (документация — отдельным заходом Vibe).
3. Часы хоста не сдвигать; периоды подбирать длиной минуты, не ускорением времени.

## Шаги

0. Ветка `stage12-testnet` от свежего main (`da7bd9c`).
1. Среда (openSUSE): остановить Gradle-демоны, закрыть браузер; `pgrep` — старых `tnp-node`/`tnp-testnet`/`qemu`/`java` нет; `go build ./...` и `go test -count=1 ./...` зелёные; собрать `tnp-testnet`, `tnp-node`. Для эмулятора проверить `/dev/kvm`; AAR — `gomobile bind -checklinkname=0` (Go 1.27); эмулятор — debug-сборка, full-узлу нужен `hw.wifi=yes`.
2. Сеть A (rec): конфигуратор — slug (например `cirrus-t`), recurring=on, unit=quota(resource_id), transfer_mode=peer-redeem, короткие периоды (период ~2 мин, epoch_seconds ~60–90 с), малые PoW-таргеты, окно челленджа открыто на момент прогона (genesis подобрать, как в 12.2), посевной круг 3, поставщик 1 (fingerprint). Флот 8–12 headless-узлов на localhost с `-link-groups=false`.
3. Чек-лист сети A (все пункты — в отчёт с [x]/[ ]):
   - [ ] регистрация + vouch×3, активация, выпуск в периоде P;
   - [ ] redeem поставщику по подписи; peer-redeem участнику; балансы сходятся;
   - [ ] граница P+1 в реальном времени: перевод единицы периода P → `E_BURNED`;
   - [ ] погашение (redeem) единицы периода P после границы → `E_BURNED`;
   - [ ] единицы периода P+1 переводимы; остаток P не перетекает в новый период;
   - [ ] сеть жива ≥3 периодов и ≥3 эпох, чекпоинты собираются;
   - [ ] рестарт одного узла из БД: холодная сверка сходится (state_root совпадает с живыми узлами), повторная публикация сгоревшей единицы после рестарта → `E_BURNED`.
4. Сеть B (std): тот же флот-модель, recurring=off (std-шаблон), те же короткие периоды. Чек-лист:
   - [ ] выпуск в периоде P; перевод единицы периода P **после** границы P+1 принимается (сгорания нет);
   - [ ] сеть жива ≥2 периодов, чекпоинты собираются.
5. Replay между сетями: подписанная tx сети A публикуется в сеть B → отвергается; tx сети B в сеть A → отвергается; tx из глобальной сети (`network_id = "global"`, std) в A/B → отвергается; tx из A/B в глобальную → отвергается; после попыток обе сети продолжают работать, журналы не смешиваются.
6. Приложение (1 эмулятор, если KVM доступен; иначе пометить BLOCKED и продолжать): rec-сборка `equality-<slug>-rec-v*.apk` — установка, онбординг «<display_name> · Eq-<hash8>», регистрация (PoW+биометрия) принята, баланс виден; перевод сгоревшей единицы из UI — понятная ошибка; рядом установлена std-сборка (другой applicationId) — обе живут одновременно, данные не перезаписываются.
7. Метрики: RSS узлов (rec/std), задержка между границей периода и первым `E_BURNED`, размер genesis-пакета, время сбора подписей чекпоинта.
8. Артефакты — `reports/stage12-testnet/` (логи, скриншоты, метрики); отчёт `reports/REPORT-STAGE-12-TESTNET.md`: чек-лист выше с отметками, находки, PENDING, метрики.
9. Уборка: остановить флот, эмулятор, Gradle-демоны; `pgrep` пуст; бинарники вне репо; рабочее дерево чистое.

## Правила

Стандартные: PENDING не додумывать; пуш ветки и merge — после подтверждения владельца (merge no-ff по разрешению делает CLI); remote-ветки не удалять; комментарии в коде русские; правки кода в этой ветке — только критические блокеры прогона, с пометкой в отчёте (остальное — находки/PENDING для отдельной мини-ветки).

## Критерий готовности

Чек-лист сети A закрыт (сгорание `E_BURNED` на реальной границе, рестарт из БД сходится); std-сеть без сгорания; replay отвергается во всех четырёх направлениях (rec↔std, global↔rec, global↔std); пункт приложения закрыт или BLOCKED с обоснованием; отчёт и артефакты в ветке; тесты `go test ./...` зелёные; дерево чистое; процессы убраны.
