# Промпт фикс-темы fix-release-keys — P1 аудита Sonnet-2: подпись релизов, герметичность

Ветка: `fix-release-keys` от свежего `main` (рабочий клон; личный клон не трогать; `audit*` запрещён). Тема: закрыть P1 аудита Sonnet-2 (a8-keys) — до подписания релиза.

Источник: reports/DIGEST-AUDIT-SONNET-2.md в main; полный отчёт: git show origin/audit-sonnet:reports/audit-sonnet/REPORT-AUDIT-SONNET-2.md (секция про release-подпись и тесты).

Шаги (только P1; P2/P3 — НЕ в этой теме):
1. verifySigning (скрипты сборки): вычислять SHA-256 файла ключа и сверять с ожидаемым отпечатком (env TNP_SIGNING_KEY_SHA256). Несовпадение — fail сборки; отсутствие отпечатка при release-сборке (wantsRelease) — fail, при обычной — предупреждение.
2. Права файлов ключей: проверка ≤0600 при сборке, нарушение — fail.
3. Герметичность тестов: configureCmd без -signing-dir (6 вызовов по аудиту) — параметризовать временным каталогом, чтобы go test на любой машине не читал и не перезаписывал реальные credentials.txt / signing.properties.
4. wantsRelease: release-сборка без ключа/отпечатка — ошибка (не молчаливый неподписанный APK); существующее поведение задач-подстрок оставить, но сообщение явное.
P2 (PKCS12 ≥32 симв., изоляция подписи на отдельной машине, RELEASE-KEYS.md + независимый канал отпечатков) — за пределами темы (решение владельца).

Тесты: юниты сверки отпечатка и прав; герметичность: go test ./... не создаёт и не трогает signing.properties вне временного каталога. go build ./... rc=0.

Отчёт: reports/REPORT-FIX-RELEASE-KEYS.md на ветке: file:line, матрица fail/warn, результаты, session-ID.

Правила: чекпоинты событийные + ~60 мин (session-ID), чистое дерево, пуш ветки, НЕ мержить. Модель и окно — YAML-шапкой.
