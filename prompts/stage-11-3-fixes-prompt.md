## Задача

1. **PENDING №2 — settle отложенных операций после рестарта узла.** Сейчас отложенная операция применяется только при живом apply-триггере (в прогоне 11.2 триггером был register). Добавить периодический flush: узел при сверке/старте доводит до применения зрелые отложенные операции (переводы D = 48 ч, смены гардианов 48 ч) без внешнего триггера. Тесты: рестарт узла после зрелости — операция применяется; незрелая — остаётся в ожидании; повторное применение исключено.
2. **PENDING №3 — заморозка приложения при таймауте биометрии.** Экран согласия гардиана: таймаут биометрии не должен вешать UI; отмена диалога возвращает экран в рабочее состояние. Widget-тест таймаута/отмены.
3. **PENDING №4 — экран History после рестарта не обновляется.** Воспроизвести, найти причину (кэш состояния экрана vs live query), починить; тест на обновление истории после рестарта узла.
4. **PENDING №6 — IME портит длинный hex.** Поля ввода длинных hex-строк (адрес, подписи): вставка из буфера может терять/искажать символы (IME-нестабильность эмуляторов). Смягчение: ввод чанками по 20 символов (отдельные поля с авто-переходом) + контроль длины/символов после вставки. Экран согласия гардиана и карточка восстановления.
5. **PENDING №7 — клавиатура перекрывает кнопки.** Экраны ввода: прокрутка (SingleChildScrollView / resize) под открытую клавиатуру, чтобы целевая кнопка оставалась доступной.
6. **Прогон по скиллу emu-run:** перед прогоном проверить `adb shell dumpsys user` на locked/keyguard (wipe-data при признаках); проверить слоты mint хелпером до регистраций (свойство «поздних слотов» №39); скриншоты в `reports/stage11-3-fixes/`; после прогона — остановить Gradle-демоны, завершить `tnp-node`/`tnp-testnet`/`qemu`, `pgrep` чист.
7. **Отчёт** — `reports/REPORT-STAGE-11-3-FIXES.md`: что исправлено по каждому пункту, тесты, скриншоты, оставшиеся ограничения среды.

## Правила

1. Протокол и спеку не менять; PENDING №1 и №5 не трогать (владелец/вне кода).
2. **Промежуточные коммиты (событийные + временные):** после каждого завершённого пункта — прогресс-коммит (код, тесты, артефакты, session-ID в сообщении); внутри длинного пункта — сверять метки времени в выводах инструментов, накопилось ~30 минут активной работы — коммит. Бинарники и scratch не коммитить; крупные временные файлы — вне репо (/tmp). Финальный коммит — чистое дерево. После рестарта сессии — до любых действий сверить живое состояние с последним коммитом и отчитаться планом.
3. Тесты: `go test ./...` зелёные (включая `-race` по задетым пакетам); `flutter analyze` чисто; `flutter test` зелёные. Известные флаки `TestVoteFinalityNetwork`, `TestSideChannelPublishPropagates` — не регресс.
4. Пуш ветки и merge в main — только после подтверждения владельца. Remote-ветки не удалять.
5. Имена файлов английские; комментарии в коде русские.

## Критерий готовности

Settle после рестарта работает без внешнего триггера (тесты); биометрия не вешает UI (тест таймаута); History обновляется после рестарта (тест); hex-поля устойчивы к IME (чанки + контроль); клавиатура не перекрывает кнопки; эму-прогон со скриншотами; отчёт `reports/REPORT-STAGE-11-3-FIXES.md`; тесты зелёные; процессы убраны; дерево чистое.
