# Промпт: мини-этап 12.3 — фикс applicationId: префикс x перед hash8

Контекст: этап 12.2 слит в main (`1e47bf5`). Находка эмуляторного прогона 12.2: формула applicationId мини-этапа 12.1 `io.equality.<sanitized-slug>.<hash8>` даёт невалидный Android-пакет в ~62.5% случаев — сегмент, начинающийся с hex-цифры, AAPT отвергает (`io.equality.cirrus.783da646`); в прогоне 12.2 обойдено подбором сети с буквы. Решение владельца: префикс `x` перед hash8 — без маппинга, инъективно. Изменение только в конфигураторе; wire, палитра, label, имена APK, display_name, спека — не трогать.

## Решения и рамки

1. applicationId = `io.equality.<sanitized-slug>.x<hash8>`; глобальная сеть — `io.equality.global.x<hash8>`. Префикс `x` ставится всегда (детерминированно и единообразно), hash8 = первые 8 hex SHA-256(network_id) — не меняется.
2. Правило Android: каждый сегмент имени пакета начинается с буквы; с префиксом `x` валидность гарантирована для любой сети.
3. Label `Eq-<hash8>`, имена APK `equality-{global|slug}-{std|rec}-v{v}.apk`, display_name, палитра, идентикон — не меняются (меняется только applicationId).
4. Обход «подбор сети с буквы» из скриптов/тестов прогона 12.2 удалить; зафиксировать в тесте сеть с цифрой в начале hash8 (например, из прогона 12.2, где применялся обход).
5. Спеку не править; расхождения (если появятся) — в раздел отчёта «для спеки» (документация — отдельным заходом Vibe).

## Шаги

0. Ветка `stage12-3-appid` от свежего main (`1e47bf5`).
1. Конфигуратор: формула `x<hash8>` в точке генерации applicationId; юнит-тесты: валидность сегмента (буква в начале) для кейсов буква/цифра в начале hash8, детерминизм, глобальная сеть, регрессия slug-санитизации (дефис → `_`), неизменность label/APK-имён.
2. Сборка end-to-end: собрать APK для сети с hash8, начинающимся с цифры (сеть из прогона 12.2 с обходом либо новая с подобранным genesis), убедиться, что AAPT принимает пакет; артефакты — reports/stage12-3/.
3. Тесты: `go test -count=1 ./...` зелёный; `-race` по задетым; `flutter analyze` — только если тронуты файлы Flutter (не планируются).
4. Отчёт `reports/REPORT-STAGE-12-3.md`: старое/новое, кейсы (буква/цифра в начале hash8), результат сборки, PENDING.

## Правила

Стандартные: PENDING не додумывать, пуш и merge — после подтверждения владельца, remote-ветки не удалять, комментарии в коде русские.

## Критерий готовности

applicationId любой сети (std/rec, slug/global) валиден по правилам Android; label/имена APK/display_name не изменились; обход подбором сети удалён; тесты зелёные; отчёт в ветке; дерево чистое.
