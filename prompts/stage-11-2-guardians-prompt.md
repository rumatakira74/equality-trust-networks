# Промпт: мини-ветка stage11-2-guardians — перевыбор личных гардианов (расширение протокола)

## Шаг 0

- Ветку `stage11-2-guardians` создать от свежего `origin/main` (git fetch).
- Если в `origin` есть ветка `stage11-prep` — НЕ трогать её и не сливать; работать от main.
- Не трогать: main, remote-ветки, README.md, доковские репозитории.

## Решение владельца (21.10.2026)

Смена личных гардианов после `register` вводится в протокол (замена прежнего ограничения D4 «назначаются навсегда»). Обоснование: сеть может запускаться без посевного круга (код открыт, кто угодно начинает сеть); личные гардианы неизменны → участник, чей гардиан исчез/умер/вышел из сети, навсегда теряет путь восстановления. Публичные гардианы (12 мес. возраста) в новой сети недостижимы первый год.

## Мандат

### 1. Протокол и ядро (Go)

- Новый тип транзакции `update_guardians` в закрытом перечне (расширение перечня — явное решение владельца 21.10.2026; прецедент D2/D4). Транзакция в цепочке владельца кошелька, подпись текущим ключом.
- Payload: новый список личных гардианов (≤ 3, как при `register`) + пары «адрес нового гардиана + подпись гардианом хеша смены» (согласие, передаётся вручную — как approve миграции).
- Проверки при публикации: новые гардианы `active`, не `flagged` (№14), лимит подопечных `guardian_personal_max_wards` (№7) не превышен; активная смена одна (повторная публикация до вступления предыдущей — отклоняется).
- Лимит смен (решение владельца 21.10.2026): не более **15 вступивших в силу** смен гардианов на кошелёк за всё время существования; счётчик вычисляется из истории цепочки кошелька (отменённые и истёкшие смены лимит не потребляют); при исчерпании транзакция `update_guardians` отклоняется.
- Окно вступления в силу: 48 ч (константа, не параметр; прецедент — отложенный перевод и повышение P). До истечения действует старый список; после — новый. Подписи гардианов для миграции валидны по списку, действующему на момент подписи approve.
- Отмена смены: подписью владельца в окне 48 ч (PIN-only). Если к моменту вступления лимит №7 у кого-то из новых превышен — смена не вступает в силу, помечается истёкшей.
- Комиссии/награды: нет. Смена видна в публичной истории кошелька.

### 2. Приложение (Flutter)

- Экран «Гардианы» в настройках: текущий список, «Перевыбрать», ввод пар «гардиан + подпись», отсчёт окна 48 ч, отмена; индикация остатка лимита смен (использовано N из 15). Доступ с экрана миграции.
- Согласие гардиана: экран подтверждения (адрес подопечного, хеш смены; биометрия — как ApproveMigrationScreen), подпись передаётся вручную.
- PIN-only: публикация и отмена смены — только явный ввод PIN (правило этапа 9); тревожный PIN → приманка: операции смены в приманке затрагивают только данные приманки, реальный список не меняется.
- i18n: все строки в ARB на 5 языках (ru, en, es, pt, zh), fallback en.
