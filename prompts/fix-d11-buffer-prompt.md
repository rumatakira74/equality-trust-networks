# Промпт фикс-темы fix-d11-buffer — офлайн-буфер публикации (awaiting) переживает рестарт

Ветка: `fix-d11-buffer` от свежего `main` (рабочий клон /home/projects/audit-equality-trust-networks; личный клон не трогать). Кодовая тема: закрыть D11 (FINDING-awaiting-offline-tx-not-persistent.txt; reports/REPORT-STAGE-16-NODE-PERSISTENCE.md §7): офлайн-буфер публикации (awaiting, Bluetooth 12.4) живёт только в памяти (net/node.go: OnOfflineTx / awaiting / PublishAwaiting) — при force stop получатель видел «принято», но платёж не опубликован.

1. Дизайн-минимум: таблица awaiting_txs в существующем персистентном store (SQLite, слой этапа 16 — использовать существующую схему и стиль миграций): запись при OnOfflineTx (транзакционно, с дедупом по txid), загрузка при старте узла, публикация через PublishAwaiting по готовности сети, удаление после успешной публикации. Комментарии по-русски.
2. Границы: сетевой протокол и консенсус НЕ менять; только персистентность буфера и его воспроизведение после рестарта.
3. Тесты: юнит (store: запись/загрузка/дедуп/удаление) + интеграционный (создать awaiting → рестарт узла = новый экземпляр на том же store → буфер восстановлен → публикация → буфер пуст). go test ./net/... зелёные; go test -race ./net/ зелёные.
4. Отчёт: reports/REPORT-FIX-D11-BUFFER.md: схема, file:line, сценарии тестов, результаты, session-ID.

Правила: чекпоинты событийные + ~60 мин (session-ID), чистое дерево, пуш ветки, НЕ мержить. Модель и окно — YAML-шапкой задачи очереди.
