# Промпт темы mint-fix — фикс окна челленджа выпуска (вариант A) + protocolVersion-bump

Ветка: `mint-fix` от свежего `main`. Решение владельца 03.11.2026: дефект подтверждён независимо трижды (симуляция A9, blind-аудит A9, внешний аудит Sonnet).

## Предмет

Дефект M7 — окно челленджа mint (7.6). В `core/ledger/validate.go` (applySigPowTime) проверка:

`if tx.Type == wire.Mint && !l.Opts.SkipMintChallengeWindow { mp := tx.Payload.(*wire.MintPayload); if !l.CheckMintChallengeWindow(tx.Wallet, mp.Period, l.tt.now) { return reject("E_POW_HARD") } }`

Слот считается от ЗАЯВЛЕННОГО периода `mp.Period` (`mintChallengeSlot`: `period_start + hashThree(addr, period) mod period_secs`, `period_start = genesis_time + period * period_secs`). Слот равномерен внутри периода (при 30 сут = 720 ч), а заявка периода P по M4 возможна только после конца P. Поэтому окно ±48 ч вокруг слота P пересекается с допустимым временем заявки только при слоте в последних 48 ч периода: достижимость 1/15 = 6,67 % за период. Слоты независимы по периодам, поэтому 6 пропусков подряд (вероятность (14/15)^6 ≈ 66 %) дают diff > accrual_window навсегда — поглощающее состояние: кошелёк навсегда теряет выпуск.

Симуляция A9 (репо eq, только чтение, отчёт `reports/REPORT-A9-SIMULATION.md` в eq main): честные −91,2 % дохода за 60 мес., к 60-му месяцу заблокированы 53 % честных кошельков; автоматизированная ферма не страдает — слот `SHA256(addr‖period)` публично вычислим заранее. Дефект бьёт ровно по тем, кого должен защищать.

## Фикс (вариант A, утверждён владельцем)

Якорь слота — текущий период выпуска: в `applySigPowTime` передавать в `CheckMintChallengeWindow` не `mp.Period`, а `l.tt.period` (период момента подачи; `l.tt` вычислен в `Apply` от txNow = tx.TimestampClaim; периоды календарные от genesis — решение №39).

После фикса слот лежит внутри ТЕКУЩЕГО периода, окно ±48 ч вокруг него всегда пересекается с текущим периодом (пересечение ≥ 48 ч): каждый период у каждого кошелька есть достижимое окно. Слот публично вычислим заранее — приложение может показать его пользователю (сам UX-показ слота — вне мандата, не делать). Пропущенный период компенсируется M6 (amount = issuance × diff) в пределах accrual_window — поглощающее состояние исчезает; осознанный пропуск 6+ периодов по-прежнему сгорает (дизайн accrual_window не меняется).

Требуется protocolVersion-bump: семантика проверки M7 меняется, старые и новые узлы разошлись бы в вердиктах.

## Мандат

1. Шаг 0 — сверка состояния: свежий main; прочитать `core/ledger/validate.go` (M7, CheckMintChallengeWindow, mintChallengeSlot), `core/params/params.go` (MintChallengeWindowHours, таргеты), `core/wire/genesis.go` (поле версии протокола, поле 61 — длина периода); убедиться, что код соответствует описанию выше. Отчитаться планом работ до правок.
2. Фикс M7: якорь слота на текущий период (`l.tt.period` вместо `mp.Period`); комментарии в коде привести к фактическому поведению (комментарии — по-русски).
3. protocolVersion-bump: найти поле версии протокола в genesis (C2 в `applyCommon`: `tx.ProtocolVersion != l.State.Net.ProtocolVersion → E_VER`), поднять на 1; обновить все дефолты, фикстуры, векторы, genesis-шаблоны cmd/tnp-testnet и тесты, где версия зашита. Живых сетей нет — миграция не нужна, зафиксировать в отчёте.
4. Единообразие M7 на всех путях применения: `SkipMintChallengeWindow` — только песочница. Проверить net (initLedger, gossip, sync/replay) и mobile-мост: если какой-то сетевой путь пропускает проверку окна (долг этапа 8: `SkipMintChallengeWindow: true` в net.initLedger), закрыть в этой теме — иначе фикс обходится подачей через sync. Все пути (headless, net, replay) обязаны приходить к одному вердикту от txNow.
5. НЕ менять: формулу слота `hashThree(addr, period)` — вопрос включения hash(чекпоинта предыдущей эпохи) из спеки 7.6 остаётся PENDING за владельцем (в отчёт, не править); M3/M4/M5/M6; genesis-поле 61; окно ±48 ч; любые другие правила ядра.
6. Тесты (все — с репродуцируемыми данными, без вероятностных допущений там, где можно детерминированно):
   (a) свойство окна после фикса: для набора адресов и периодов пересечение [slot−48 ч, slot+48 ч] с текущим периодом всегда ≥ 48 ч;
   (b) mint в окне текущего периода проходит; вне окна → E_POW_HARD;
   (c) заявка старых периодов (накопление, diff ≤ 6) в окне текущего периода проходит (amount по M6);
   (d) 6+ пропусков → E_ACCRUAL_WINDOW (не изменилось);
   (e) live == replay: окно от txNow — вердикт детерминирован (один журнал — один state_root);
   (f) песочница: SkipMintChallengeWindow → окно не проверяется;
   (g) tx с прежней protocolVersion → E_VER;
   (h) дофиксный вектор (фиксирует смену семантики): txNow после конца заявленного периода при слоте заявленного периода в середине → E_POW_HARD (ранее окно могло открыться по заявленному периоду — теперь нет).

## Правила

- Чекпоинты: прогресс-коммит после каждого завершённого пункта/цикла тестов; ориентир ~30 мин активной работы по меткам времени в выводах; session-ID в сообщениях коммитов. После любого рестарта сессии — до любых действий сверить живое состояние с последним коммитом ветки и отчитаться планом; ничего не повторять без сверки.
- Стоп-вопрос: при блокере (нужно действие, доступное только владельцу) или неоднозначности с риском ошибки/напрасной работы — один конкретный вопрос в чате, продолжать после ответа.
- Файлы >1 МБ не коммитить; бинарники и scratch — вне репо; перед add проверять git status; финальный коммит — чистое дерево.
- Уборка процессов: после прогонов остановить Gradle-демоны и завершить оставленные go/tnp-процессы (проверка pgrep перед следующим прогоном и в финале).
- Пуш ветки — после полного локального набора. Merge — только по подтверждению владельца (диспетчер в Telegram). Статусы CI в сессии не ждать — в отчёте «CI pending».
