Модель сессии — только в YAML задачи (транспорт лаунчера), в этот текст не входит.

## Источники (читай до действий, живыми данными)

3. **Репо проекта** `rumatakira74/equality-trust-networks` (tnp): ветки, свежие коммиты, промпты в `prompts/`.

## Порядок работы

1. Прочитай базу (п. 1) — последние эпизоды дают план конвейера и правила; их решения имеют приоритет над твоими догадками.
2. Снимок: queue/ + processed/ + results/ (последние сводки прочитай), state.json, pipeline.json, ветки и коммиты tnp.
3. Реши и сделай то, что делал бы Vibe при перечите. Типовые шаги (список не исчерпывающий, сверяйся с эпизодами):
   - упавшая `.failed`-задача без диагностики в results/ → поставить ретранслятор `fetch-diag` (deepseek-flash, low, 30);
   - завершённая тема без следующей → поставить следующую задачу конвейера (аудит / тема / деплой) по плану из эпизодов; формат задачи — ниже;
   - диспетчер молчит (last_run старше 1 ч, конвейер ждёт его действий) → `TRIGGER.txt` в корень репо диспетчера (механика — прецедент: коммит `0d66b41` 03.11 20:03 UTC; устройство файла сверь с историей репо);
   - аудит .done, отчёт есть в ветке аудита, а в main его нет → дайджест: перенеси отчёт аудита в main tnp (арбитраж по правилам базы) — НО только если в аудите нет блокеров; чистый дайджест разблокирует авто-merge (тема auto_merge: диспетчер смержит сам ближайшим прогоном ≤30 мин);
   - в аудите есть блокеры/несколько вариантов выхода → отчёт в main НЕ переносить (без дайджеста авто-merge не случится), ветку аудита не трогать; варианты с обоснованием — в сводку для владельца/Vibe (решение — только владельца);
   - тема готова к merge, блокеров нет → НЕ мержить сам и ничего не ставить: merge делает диспетчер автоматически (auto_merge), кнопка владельца — резерв;
   - видна безопасная косметическая проблема (лента, тексты) → правь, если не нарушает правила.
4. Формат задачи в очередь — файл `cli-jobs/queue/<NNNNNNNN>-<topic>.md` (серийник 8 цифр = max(queue + processed) + 1):

```
---
topic: <topic>
target_repo: <КЛЮЧ: tnp | eq>
prompt_path: prompts/<файл>.md

thinking: <уровень>

---
<стартовое сообщение БЕЗ модели: исполняй промпт буквально; секреты не коммитить; в конце только сводка>
```

5. Сводка: `cli-jobs/results/<твой-серийник>-pipeline-run.md` (≤32 КБ): снимок, решения и их обоснование, что сделано, что дальше, что требует Vibe/владельца. Поставленную задачу (если была) и сводку — ОДНИМ последним коммитом через /tmp-клон репо диспетчера; после него в git не писать.

## Жёсткие правила (из cli-bridge.md, обязательные)

- Не пушить в репо диспетчера при живой чужой задаче в queue/ (твой собственный файл в queue/ — норма); новая задача — только при пустой очереди и последним действием сессии.
- Живые клоны на машине принадлежат лаунчеру — не трогать; свои коммиты — только через свежие временные клоны в /tmp (clone → правка → commit → push → удалить клон).
- `launcher.sh` не читать и не менять; `target_repo` — только КЛЮЧ (tnp/eq), не полный путь (урок 00000017).
- Никогда не коммитить секреты (токены, ключи, содержимое ~/.vibe/config.toml).
- Модель/thinking исполнителя — только в YAML-шапку задачи, не в текст.
- Merge — никогда сам: при полной готовности merge делает диспетчер автоматически (auto_merge; политика владельца 03.11); решение человека — только при ошибках с вариантами: тогда дайджест в main не делать, варианты — в сводку (hold в тему ставит Vibe).
- В базу знаний (зеркало) не коммитить — территория Vibe; всё, что должен узнать Vibe, пиши в сводку results/.
