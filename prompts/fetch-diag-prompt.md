# Диагностический ретранслятор fetch-diag — вынести результаты диагностик в git и R2

**Предусловие:** это диагностика-ретранслятор, НЕ тема конвейера. Репозиторий кода (tnp, текущий workdir) read-only: никаких коммитов, правок, веток, пушей в нём. Секреты (api-ключи, токены, пароли) не выводить ни в каком виде — если встречаются в файлах, писать только «секрет присутствует, скрыт».

## Задача

Сессия r2-check (задача 00000004) уже отработала: её сводка — в локальном логе, причина .failed задачи A8 (00000003) — в логе лаунчера. Вынести эти результаты в git и R2, чтобы Vibe прочитал их без ручной пересылки владельцем.

## Шаги

### 1. Прочитать (только чтение)
- `/home/projects/mistral-harness-workflows/cli-jobs/logs/launcher.log` — хвост 120 строк; выписать точные строки с причиной .failed задачи 00000003-a8-keys (предзапускная проверка или ошибка сессии).
- `/home/projects/mistral-harness-workflows/cli-jobs/logs/00000004-r2-check.log` — полный текст или хвост 200 строк; из него — сводку r2-check: результаты wrangler/R2 по шагам (version, whoami, bucket list, put/get/delete), список alias моделей, свободная память.
- Если `logs/00000003-a8-keys.log` существует — хвост 60 строк.
- Если данных в логах не хватает (например, списка моделей) — восполнить самому: `~/.vibe/config.toml` — ТОЛЬКО имена из блоков [[models]] (name = "...") и thinking_levels; секреты скрыть. `free -m`, `uptime`.

### 2. Сформировать отчёт (файл /tmp/diag-2026-11-03.md)
Структура:
- `## 1. Причина .failed задачи 00000003-a8-keys` — цитаты строк лога;
- `## 2. Сводка r2-check (00000004)` — результаты wrangler/R2 по шагам (put/get/delete — статус), версия wrangler;
- `## 3. Alias моделей CLI` — список имён из config.toml; отметить, есть ли `zai-glm-5-3` и как именно называется GLM 5.3 в конфиге;
- `## 4. Ресурсы` — свободная память, uptime;
- `## 5. Вывод` — что нужно, чтобы задача A8 стартовала (alias / память / иное).

### 3. Публикация
- **R2:** `wrangler r2 object put tnp-artifacts/results/diag-2026-11-03.md --file /tmp/diag-2026-11-03.md`; при ошибке — записать её точный текст и продолжить.
- **Git-дайджест (обязательно):** временный клон приватного репо: `git clone /home/projects/mistral-harness-workflows /tmp/whf-results` и работать только в нём (живой клон /home/projects/mistral-harness-workflows НЕ трогать — им владеет лаунчер); создать `cli-jobs/results/diag-2026-11-03.md` с содержимым отчёта (файл до ~32 КБ — кладётся целиком); коммит `results: 00000005 fetch-diag — причина .failed A8 + сводка r2-check`; push в origin main. Если push не удался — записать точную ошибку.
- После публикации — убрать временные файлы /tmp (клон удалить).

## Правила
- Репозиторий кода не менять; в приватный репо — только один файл cli-jobs/results/diag-2026-11-03.md одним коммитом.
- Секреты не печатать.
- Стоп-вопросы не задавать; при блокере — записать его и продолжить остальные пункты.
- В конце — ТОЛЬКО сводка: причина .failed A8; R2-публикация — статус; git-публикация — статус. Без вопросов.
