# Промпт: мини-ветка stage11-1-fixes — фиксы находок прогона stage11-prep

Выполняй шаги строго по порядку. Каждый пункт — одна законченная инструкция.

## Находки (из reports/REPORT-STAGE-11-PREP.md, раздел «Находки прогона»)

1. №1 — подписи Android Keystore (Kotlin-путь, NONEwithECDSA) не нормализуют s; ~50% register-подписей приложения отвергаются ядром с E_SIG (ядро с этапа 9 требует каноничный DER + low-s).
2. №2 — mobile/query.go MintWindowJSON передаёт в QueryMintWindowOpen текущий период, а ядро (M7, №39) проверяет слот заявляемого периода — кнопка Mint отключена при фактически открытом окне.
3. №5 — StartMigrationScreen генерирует случайный nonce и не показывает его — гардиан не может подписать MigrateStatement; публикация миграции из приложения невозможна.
4. №6 — configure не выставляет migrate_delay_days (genesis-поле 49); в прогоне выставлено пост-обработкой хелпером.
5. Спека — в docs/KNOWLEDGE-ENG-4.md пункт «Known v1 limitations» продублирован (внутри списка гардианов и в конце раздела 11).

## Шаг 0 — подготовка

1. git fetch.
2. Создать ветку stage11-1-fixes от свежего origin/main.
3. Не трогать: main, remote-ветки, доковские репозитории, README.md.
4. Известные падения net-тестов (TestVoteFinalityNetwork, TestSideChannelPublishPropagates) воспроизводятся и на чистом main — регрессом не считать, не чинить.

## Шаг 1 — фикс №1: low-s в Keystore-подписях

1. Нормализовать подпись в Kotlin-пути (KeystoreWallet.sign / BiometricGate): если s > n/2, заменить s на n − s; на выходе — каноничный DER, проходящий проверку ядра.
2. Юнит-тест нормализации: вектор с высокой s → нормализована; каноничность DER сохранена.
3. Ядро (проверку подписей) не менять.

## Шаг 2 — фикс №2: окно челленджа в UI

1. MintWindowJSON передавать заявляемый период (следующий незаявленный период кошелька), а не текущий.
2. Тест: при открытом окне заявляемого периода — окно открыто; вне окна — закрыто.
3. Правила M4 и №39 (календарные периоды от genesis) не менять.

## Шаг 3 — фикс №5: nonce в StartMigration

1. Показать nonce на экране StartMigration с возможностью копирования.
2. Widget-тест: nonce отображается до ввода подписей гардианов.
3. Экран Approve и протокол миграции не менять.

## Шаг 4 — фикс №6: -migrate-delay-days в configure

1. Добавить флаг -migrate-delay-days в tnp-testnet configure → genesis-поле 49.

## Шаг 6 — проверочный прогон (по скиллу emu-run)

1. Собрать учебную сеть как в stage11-prep (конфигуратор, шаблон «Лаборатория», короткая эпоха; окно миграции — через новый флаг -migrate-delay-days 1).

3. В открытом окне челленджа кнопка Mint активна; выпуск из приложения проходит.
4. На экране StartMigration nonce виден.
5. Если IME-нестабильность блокирует шаг — зафиксировать в отчёте и закрывать шаг по тестам; не застревать.

## Правила

- Промежуточный коммит: после каждого завершённого шага и раз в ~30 минут активной работы. В сообщении коммита — session-ID.
- После рестарта сессии: сверить живое состояние с последним коммитом ветки и отчитаться планом. Ничего не перезапускать без сверки.
- PENDING не додумывать: зафиксировать в отчёте и идти дальше.
- Финальный коммит — чистое дерево. Скриншоты — в репо; бинарники и scratch — нет.
- Пуш ветки и merge в main — только после подтверждения владельца.
- Remote-ветки не удалять.
