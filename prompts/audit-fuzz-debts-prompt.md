# Тема Blind-аудит ветки fuzz-debts (процесс и покрытие тестов) — ветка audit-fuzz-debts (только чтение и reports/)

**Предусловие:** ветка `fuzz-debts` запушена (tip `ef06af9`, CI 8/8 зелёные на момент выдачи темы; если tip ушёл — работать по текущему tip, сверив предусловия, при сомнении — стоп-вопрос). Запуск — по команде владельца (дана). Ветка `audit-fuzz-debts` — **от текущего tip ветки `fuzz-debts`** (не от main: аудит должен видеть код темы). **Режим: только чтение и `reports/` — код, тесты, спека, README, промпты НЕ трогать; находки не править (правки — отдельное решение владельца).** Основание: схема контроля качества темы fuzz (исполнитель → CI-verify → blind-аудит → merge по подтверждению владельца). Живых сетей нет. Правило CI-verify: сессия НЕ ждёт статусов CI.

**Слепость:** аудит независимый. Пункты 1–5 выполняются ДО открытия отчёта исполнителя `reports/REPORT-FUZZ-DEBTS.md`; его заявления — не истина, а гипотеза для сверки в пункте 6.

**Цель:** механически проверить полноту и качество исполнения мандата `prompts/fuzz-debts-prompt.md` по факту кода и тестов; выдать вердикт готовности ветки к merge.

**Пункты:**

1. **Полнота мандата (7 задач).** По каждой задаче мандата — статус по факту кода: (1) инвентаризация недоверенного ввода (таблица «функция → источник → лимиты есть/нет»); (2) fuzz-цели на каждую группу декодеров (`core/wire`, `net/codec.go`, `core/attest`, genesis-декодеры); (3) локальные прогоны с `-fuzztime` и фиксы крашей; (4) property-тесты инвариантов (`ledger.Apply` + `CheckInvariants`/`FullCheck`); (5) юнит-тесты `core/store`; (6) proto-сверка (`proto/*.proto` ↔ ручной кодек); (7) отчёт. Каждая — доказательство: файл/строка/название теста.

2. **Качество fuzz-целей.** Каждая цель: seed-корпус (валидные векторы из существующих тестов + граничные: пустой ввод, усечение, переполнение varint, вложенная глубина, гигантские заявленные длины); ошибки декода возвращаются ошибкой, не паникой; лимиты размера/глубины/количества полей добавлены и обоснованы. Отсутствие лимита в точке недоверенного ввода — FINDING. Локальная проверка: `go test` по fuzz-пакетам (seed-корпуса прогоняются штатно); при необходимости — smoke-`-fuzztime` до 60 сек на цель, суммарно до ~10 мин, только с ресурсными правилами ниже. Повторять 30-минутные прогоны исполнителя НЕ нужно.

3. **Покрытие точек недоверенного ввода.** Сверить инвентаризацию из мандата (все `DecodeXxx` в `core/wire`, `net/codec.go` (`readFrame`, `dec`, `decodeHeaders`, `decodeProof`, `decodePeers`), `core/attest` (`parseKeymint`, `scanAuthorizationList`, `derScanner`, `parseExtension`, `DecodeChain`, `Verify`), genesis-декодеры) с фактическими fuzz-целями: каждая точка покрыта или осознанно исключена с обоснованием. Пропуск — FINDING высокой значимости.

4. **Property / store / proto-сверка.** Инварианты проверяются после каждого шага (не только в конце последовательности); store-тесты покрывают round-trip `SaveTx`/`LoadTxs`, fingerprints, blacklist, checkpoint headers/supply, meta, восстановление после `Close`/`Open`; proto-сверка реально ловит дрейф: разрешено локально повторить санити-мутацию `.proto` (НЕ коммитить, обязательно откатить) и показать, ловит ли её тест. Мутация без отката — нарушение режима, не допускать.

5. **Процесс и гигиена ветки.** `git diff main...fuzz-debts` — только предмет темы: fuzz-цели, тесты, лимиты, `testdata/fuzz/`, отчёт, спека-синхронизация по факту wire-фиксов. Правки вне мандата (net-DoS, UI, фиксы F5/F16, genesis-семантика, `protocolVersion`, README-эталон) — FINDING «вне мандата». Форматирование — отдельным коммитом; событийные коммиты; артефакты темы до ~5 МБ, файлов больше 1 МБ нет; корпусной кеш `GOCACHE` не закоммичен.

6. **Сверка с отчётом исполнителя.** Только теперь открыть `reports/REPORT-FUZZ-DEBTS.md`: каждое ключевое заявление (число целей, бюджеты и результаты прогонов, «0 крашей», список фиксов, результаты property/store/proto-сверки) — подтверждено кодом/тестом/коммитом или расходится (цитата + факт). Расхождения — в таблицу.

7. **FINDING вне мандата.** Крипто-безопасность — контур 2 (Large 4/Claude): крипто-наблюдения — с пометкой «вне мандата, контур 2», глубоко не исследовать. Ветки `fuzz-debts-ab` и `main` — только база сверки, не аудитировать.

**Ресурсные правила (обязательно):** лимиты в коде-под-тестом ДО прогонов; `GOMAXPROCS=6` (≤6 из 8 ядер), воркеры задавать явно (`-parallel=N`), цели последовательно; стоп при <2 ГБ свободной памяти или тормозах машины → FINDING + стоп-вопрос. После прогонов — остановить go-процессы и оставленные демоны (`pgrep`).

**Отчёт:** `reports/REPORT-AUDIT-FUZZ-DEBTS.md` — таблица «задача мандата → статус → доказательство → замечание», таблица находок (FINDING: файл/строка, значимость, рекомендация — НЕ реализовывать), таблица сверки с отчётом исполнителя, вердикт: **«готова к merge» / «готова с замечаниями» / «не готова»** со списком блокеров. Артефакты — `reports/audit-fuzz-debts/` при необходимости.

**Правила:** только чтение + `reports/`; событийные коммиты (только reports/); после рестарта сессии — сверка живого состояния с последним коммитом ветки и отчёт планом; не коммитить файлы больше 1 МБ; стоп-вопрос при блокере (нужно действие владельца / риск ошибки, напрасной работы или перерасхода токенов); финал — чистое дерево, пуш ветки `audit-fuzz-debts`; merge НЕ делать — только после дайджеста Vibe и подтверждения владельца; в конце — сводка (tip ветки, статусы по пунктам 1–7, перечень FINDING, вердикт, путь отчёта), без вопросов.
