# Промпт темы fix-ci — починка красного CI ветки темы (generic, v1.0 04.11.2026)

Имя ветки и упавшие чеки приходят в стартовом сообщении задачи. Ставит watcher-звено по флагу ci_red_persistent в state.json (диспетчер v1.9.2: CI красный после авто-реранов). Работай ТОЛЬКО в существующей ветке темы — никаких новых веток; префикс audit* запрещён.

Шаги:
1. Рабочий клон /home/projects/audit-equality-trust-networks: git fetch origin && git checkout <ветка из стартового сообщения> && git reset --hard origin/<ветка>. Личный клон /home/projects/equality-trust-networks НЕ трогать.
2. Причина падения: gh run list --branch <ветка> --limit 5; gh run view <номер> --log-failed — точное имя теста/пакета, паника или таймаут.
3. Реприз локально: go test -count=1 -run <имя> ./<пакет>/... и весь пакет. Локально зелёный — искать средозависимость (таймауты медленного раннера, права файлов/umask в CI, параллельность, порядок) и закрепить тест (стабильный таймаут, t.Parallel аккуратно, skip по env только как крайняя мера с комментарием-русским). Падение настоящее — минимальный фикс кода.
4. Проверки: go build ./... rc=0; go test ./... зелёный; gofmt -l чисто. Коммиты на той же ветке. НЕ мержить — merge сделает диспетчер при зелёном CI (auto_merge).
5. Идемпотентность: если CI на ветке уже зелёный (авто-реран помог) — НИЧЕГО не править, только верификация (go test ./...) и сводка.
6. Отчёт reports/REPORT-FIX-CI-<тема>.md на ветке: причина падения CI, что сделано (file:line), результаты проверок, session-ID. Сводка в cli-jobs/results/ через временный клон в /tmp (≤32 КБ). Чекпоинты событийные + ~60 мин (session-ID), чистое дерево, секреты не коммитить.
