# RELEASE-KEYS — отпечатки боевых сертификатов подписи APK

Публичная информация для участников и поставщиков. Боевые (release) APK
платформы подписываются двумя сертификатами; приватные ключи хранятся
только на машине владельца (вне git и CI) — обновления приложения
подписываются теми же ключами, отпечатки ниже позволяют проверить любую
установленную APK до доверия ей.

| Назначение | Ключ (alias) | Сертификат SHA-256 | Дата генерации |
| --- | --- | --- | --- |
| Все std-сети (включая глобальную сеть) | `tnp-std` | `deb05e1f59843a676bb15c6782919af6d418240a2cf2ffa5b6b989b9e9efc9f4` | 03.11.2026 |
| Все rec-сети (recurring, коммерческая сборка) | `tnp-rec` | `fa35d49d234d67a7b07fe873da7d9de5db3ea177335fe9b73c371868822aea39` | 03.11.2026 |

Параметры ключей: RSA 4096, срок действия сертификата 10000 дней
(~27 лет, до 21.03.2054), отдельные keystore-файлы `tnp-std.jks` /
`tnp-rec.jks` с отдельными паролями keystore и ключа. Имена APK по
конвенции: `equality-{global|slug}-{std|rec}-v*.apk` — суффикс `std`/`rec`
всегда соответствует ключу подписи.

## Проверка установленной APK

```sh
apksigner verify --print-certs equality-global-std-v1.0.0.apk
# Signer #1 certificate SHA-256 digest обязана совпадать с отпечатком
# tnp-std из таблицы выше (для rec-сборок — с tnp-rec)
```

`apksigner` входит в build-tools Android SDK
(`$ANDROID_HOME/build-tools/<версия>/apksigner`); для установленного
приложения путь к APK: `adb shell pm path <applicationId>` →
`adb pull <путь> app.apk`.

## Цепочка доверия

- release-сборка без боевых ключей невозможна: градл отвергает её с
  явной диагностикой (signing-конфиг генерирует конфигуратор
  `cmd/tnp-testnet configure`, вид ключа — std/rec по типу сети).
- CI боевых ключей не имеет и release-APK не собирает.
- Владение и передача ключей (мультиподпись релизов, раздел 13 README) —
  отдельное решение владельца; этот файл фиксирует только отпечатки.
