Version 9.10 (the owner's decisions of October 27, 2026): profile 8 "Subscription resource" — `recurring` units (Section 4: each unit carries a period mark `period`; transferring a unit of period P is rejected after the boundary of period P+1; not a balance reset — the history stays verifiable; default `recurring = off`); network identification: a self-certifying `network_id = H(manifest ‖ genesis)` plus a human-readable `slug` (a label, not identity); the reserved constant `network_id = "global"` for the global network (there is no empty identifier — cross-network replay protection works in the global network too); a new transfer mode `peer-redeem` (member → member and member → provider) for the flow of recurring quotas between members; genesis validation of combinations: `recurring = on` only with a non-global `network_id`, `unit = quota(resource_id)`, and `transfer_mode ∈ {restricted, peer-redeem}`; APK file names: `equality-{global|slug}-{std|rec}-v{version}.apk` (ergonomics and license transparency, not identity); `recurring = on` is the technical marker of commercial use (Section 16.2).

Version 9.11 (the owner's decisions of November 1, 2026, mini-stages 12.2–12.3): the manifest consists of public keys — the seed circle (3.3) and providers (6.2) are defined in the manifest and genesis by fingerprints (public keys; fingerprint = SHA-256(attestedPublicKey ‖ protocolId), Section 7.2), not addresses; addresses are not stored in the manifest and are derived from the final network_id: `address = SHA-256(fingerprint ‖ network_id)` — a single derivation point (Section 7.2), so the self-certification `network_id = H(manifest ‖ genesis)` is not circular; wire-genesis: SeedMember has a single public_key field (the address field is removed; v9.10 genesis binaries are incompatible); a provider need not be a seed-circle member; at network assembly duplicate fingerprints and empty keys are rejected; the configurator: applicationId = `io.equality.<sanitized-slug>.x<hash8>`, the global network — `io.equality.global.x<hash8>` (hash8 is the first 8 hex of SHA-256(network_id), as in the `Eq-<hash8>` label; the `x` prefix is Android's requirement on the first character of a package segment; a configurator artifact, not a protocol one).

Version 9.12 (stage 14 — attestation, per the audit of November 1, 2026, findings A1/A2/A12): leaf binding — the SPKI of the leaf certificate equals the registered `attestedPublicKey` (a mismatch — `E_ATTEST_KEY_MISMATCH`), a chain cannot be reused for a different key; both Google hardware attestation roots are embedded (the current RSA one and the new ECDSA P-384 one for Remote Key Provisioning), a chain is valid if it reaches any of them; synthetic roots — only with `sandbox = true` (a non-sandbox network with a synthetic root does not start), a zero PoW target outside the sandbox is an invalid genesis; the leaf's validity period is checked at the registration's `timestamp_claim` (replay = live); honest wording (7.1, 7.2, 7.6, 3.3): attestation confirms a real device with protected hardware, but not the uniqueness of a device — several attested keys per device are possible even after the fix, the main barrier is vouching; no measurement on live devices has been performed, the DISCLAIMER remains. The transaction and genesis format does not change — only validation; `protocolVersion` is not bumped.

Version 9.13 (stage 15 — the time fix, per the 12-testnet run finding FINDING-replay-live-divergence and the owner's decisions of November 1, 2026): the validation time is txNow = `timestamp_claim` for all time-dependent rules (M2, M4, M7, T3, V2, recurring burn, evidence/deadlines, `ActivatedPeriod`, modules): one tx — one deterministic verdict, live = replay by construction, determinism between nodes at the period boundary is guaranteed (M4/M5 semantics: a completed period is claimed relative to the claim's validation period, not the publication moment); C9 (the ±30 min tolerance) is a network admission layer: checked on tx accept/relay, the core and replay do not apply it, in sandbox the tolerance is managed (not applied); settlement (demurrage, burning, period boundaries, deferred-operation deadlines) — monotonic from max(txNow) over the journal of accepted txs, never rolls back, idempotent, survives a restart; the mint challenge slot (7.6) is computed from the claim, must lie within the claim window, is scaled by `period_seconds` (field 61), the reachability of the seed circle's first claimable periods with short `period_seconds` is set by `mint_challenge_window_hours` (field 51); the std semantics of "touched" units is formalized: with `fresh_transfer_window = 0` the first spend moves all of a wallet's cohorts into Liquid, reset burning (quota_reset without recurring) affects only untouched cohorts; `protocolVersion` is bumped to 2 (the validation/settlement semantics changed; no migration — there are no live networks, test ones are re-created).

Version 9.14 (the mint-fix topic, the owner's decision of November 3, 2026; the M7 defect confirmed independently three times — the A9 simulation, the A9 blind audit, the external Sonnet audit): the mint challenge slot anchor (7.6) is the CURRENT issuance period (the txNow period), not the claimed one: period P can only be claimed after P ends (10.1), so the ±48 h window around the claimed period's slot intersected the allowed submission time only when the slot fell in the last 48 h of the period (reachability 1/15 per period; six consecutive misses — an absorbing state: a wallet lost its issuance forever, simulation A9 — honest wallets at −91.2% of income over 60 months, while an automated farm was unaffected). After the fix the slot lies inside the current period: the intersection of the ±48 h window with the current period is always ≥ 48 h — every wallet has a reachable window in every period; the slot is publicly computable in advance (`H(address ‖ period)`; including hash(previous epoch's checkpoint) is an open question, PENDING for the owner), the app can show it to the user; a missed period is compensated within the `accrual_window` (10.1), a deliberate skip of 6+ periods still burns; `protocolVersion` is bumped to 3 (the M7 check semantics changed; no migration — there are no live networks, test ones are re-created).

Version 9.15 (the a10-docs topic, documentation to the facts after A9 — PENDING-2 of the A9 blind audit): Section 7.7 brought to the facts of the A9 recalculation (under the platform's actual parameters) with the AUDIT-A9-01..11 remarks taken into account: the device cost is a model parameter, not a constant ($200; sensitivity $120/$300; the break-even price at 60 months $0.0053 / $0.0085 / $0.0125); the $0.01 crossing — in month 54 at $200 (in month 39 at $120), the metric check horizon ≥ 5 years (the metric wording in 7.6 updated accordingly); a caveat on several wallets per device added — the A1 bypass via Android profiles (2–4 wallets, a cost of $2–25/wallet) raises the farm share peak to 51.7–59.3% and lowers the break-even price to $0.0022–0.0044, A1 holds only under a strict 1:1; PoW is a rate limiter, not a cost ($2.9·10⁻⁶/month and 17.4 s per issuance at targets 2^56/2^40, Argon2id 32 MiB × 1 × p=1; the GPU/ASIC advantage ≈182×/506×); the mint challenge window — per the v9.14 fix in main (the slot anchored to the current issuance period, the absorbing state eliminated); the "income < cost" metric holds due to the device cost and purchased vouches, not due to PoW and not due to the mint window.
